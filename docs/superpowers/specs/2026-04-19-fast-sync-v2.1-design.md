# Fast Sync v2.1 — Technical Specification

## Motivation

Delta sync v2 gave us per-file granularity and resumability, but sync + backup
stages together take 20+ minutes on a 1 GB Minecraft world at residential
bandwidth. Two reasons:

1. **Sequential per-file I/O.** Single worker sends one R2 round-trip at a time.
   Latency × file count = the wall clock. At 40 Mbps with 500 changed files, the
   pipe sits idle ~50% of the time waiting for R2 responses.
2. **Per-file Copy storm on backup.** Each retained backup invokes
   `CopyObject(worlds/path → backups/{ts}/worlds/path)` for every file.
   Measured production: ~10 minutes just to create one R2 backup. R2 also
   intermittently stalls mid-loop.

v2.1 is a foundational rework of the on-disk/on-R2 layout plus the execution
model around it. It keeps delta sync's core property (only changed files go on
the wire) and adds three orthogonal speedups:

- **Content-addressed blob store** — every file identity is its xxhash; snapshots
  are JSON pointers into a shared blob pool. Eliminates the backup Copy storm
  entirely: a backup on R2 becomes one tiny JSON PUT.
- **Concurrent workers** — 16 parallel uploads/downloads fill the bandwidth pipe
  during R2 round-trip waits. Dominates the latency tax.
- **Zstd compression on blobs** — measured ~5× reduction on a real 39 MB MCA-
  heavy world. Half a second of CPU saves ~80% of wire time.

Together: **20 min → ~30 s at 40 Mbps**, **30 min → ~45 s at 20 Mbps**.

---

## Goals

- Upload a 1 GB world with medium session churn in < 1 min at 40 Mbps.
- Backup stage completes in < 5 s regardless of world size.
- Restore any retained snapshot (self-service via Explorer OR via Ritual).
- Storage local + remote deduplicated across retained snapshots.
- Zero corruption risk — atomic manifest commit is the world's source of truth.
- No resurrection of tar/streamer semantics. Streamer package stays dead.

## Non-goals

- Intra-file resumable uploads (32 MB file retries from zero — acceptable at
  Minecraft file sizes).
- `io.Reader`-based port (`[]byte` stays on `StorageRepository`).
- Branch/merge semantics (linear per-world timeline, locks already enforce
  single-writer).
- R2-side self-service restore without tooling (local side stays Explorer-
  browsable; remote needs Ritual or a small script).

## Key Changes from v2

| v2 (current) | v2.1 (target) |
|---|---|
| `worlds/` + `sync/{lockID}/` + `backups/{ts}/worlds/` on R2 | `objects/{hash}.blob.zst` + `manifests/*.json.gz` on R2 |
| 3 R2 ops per changed file (Put + Copy + Copy) | 1 R2 op per changed file (Put to `objects/`) |
| Sequential per-file sync | 16-worker concurrent pool |
| Raw bytes on wire | Zstd -3 compressed on wire and at rest |
| Path-addressed blob keys | Content-addressed by xxhash |
| Remote backup = per-file Copy loop | Remote backup = 1 JSON PUT |
| Local backup = raw tree copy | Local backup = hardlink tree into local `objects/` |
| Retention ages out backup dirs | Retention ages out manifests + GC orphan blobs |
| No multi-tier retention | Configurable tiers: last/daily/weekly/monthly |

**Target: meaningful negative LOC.** Removing staging-folder orchestration,
per-file Copy loops, and separate backupper implementations offsets the new
concurrency + compression + manifest-store code.

## Directory Layout

### Remote (R2)

```
objects/{hash}.blob.zst            <- content-addressed blobs, zstd -3 compressed
manifests/current.json.gz          <- pointer to live world state (gzipped)
manifests/{ts}.json.gz             <- per-snapshot manifest (gzipped)
```

No `worlds/` tree on R2. No `sync/{lockID}/` staging. The live world is
expressed by `manifests/current.json.gz` pointing at hashes in `objects/`.

Timestamp format: `2026-04-19T22-30-45Z` (ISO 8601 with dashes substituted so
the string is a valid path segment on every filesystem including Windows).

### Local

```
./worlds/                          <- regular files, Minecraft reads/writes
./objects/{hash}.blob.zst          <- mirror of R2 objects, shallow retention
./backups/{ts}/worlds/**           <- hardlink trees into objects/ (~0 bytes each)
./manifests/current.json.gz        <- local mirror of remote current
./manifests/{ts}.json.gz           <- local snapshots (shallow retention)
```

Local `objects/` is constrained by a separate (typically shallower) retention
policy. Hardlinks give backup trees for free — the OS presents them as real
files, Explorer shows real files, `CopyFile` works, drag-and-drop works.

### Why `worlds/` stays as regular files (not hardlinks into objects/)

Minecraft mutates region files in place during runtime. Hardlinking
`worlds/r.0.0.mca → objects/{hash}.blob.zst` would corrupt the immutable blob
the moment the server starts. Windows NTFS does not support copy-on-write, so
there is no safe way to hardlink a mutable file. `worlds/` holds its own
uncompressed bytes; download materializes them from `objects/` by decompressing.

## Content-Addressed Blob Store

### Blob identity

```
hash = xxhash64(raw_file_bytes)           // deterministic, fast, non-crypto
key  = objects/{hex(hash)}.blob.zst       // stored compressed
```

Hash is always computed over **raw content**. Storage format is always
zstd-compressed. This keeps identity stable regardless of compression settings
and lets us verify integrity on download by decompressing and re-hashing.

Hash collision risk for xxhash64 with ~1000 files × 10-year worlds: negligible
(< 10⁻¹⁵ by birthday bound). Same hash function as v2.

### Blob immutability

Blobs are write-once. A `PutBlob(hash, data)` for an existing key is a no-op (or
a conditional `If-None-Match` PUT to avoid re-upload). Two clients with the same
raw bytes converge on the same key with identical compressed content (zstd-3
deterministic output for a fixed level).

### Integrity verification on download

```go
compressed := remote.GetBlob(hash)
raw := zstd.Decompress(compressed)
if xxhash64(raw) != hash {
    return errors.New("blob integrity mismatch")
}
```

~10 ms per 10 MB file. Catches R2 corruption, truncated downloads, tampering.

## Manifest Format

```json
{
  "timestamp": "2026-04-19T22:30:45Z",
  "parent": "2026-04-18T22:30:45Z",
  "files": {
    "world/region/r.0.0.mca": "a1b2c3d4e5f67890",
    "world/region/r.0.1.mca": "1234567890abcdef",
    "world/level.dat": "fedcba0987654321"
  }
}
```

- `timestamp` — RFC 3339 UTC; also encoded in the filename
- `parent` — previous manifest this session was played on top of (nullable for
  first manifest; points at filename timestamp)
- `files` — full path-to-xxhash inventory. Complete world snapshot, not a diff.

**No schema version field** — project is pre-1.0 alpha, schema evolves freely.
The top-level `ManifestVersion` stays `"2.0.0"` (per commit `80e3ef8`) and does
not bump for this work. Shape changes are detected by field presence:
`manifests/` prefix existing + non-empty means v2.1 layout is active.

### Why full inventory, not a diff

Each manifest is self-contained. Restore reads one manifest and reconstructs the
whole world. No history traversal. Deleting one manifest never breaks another.
See **Restore Pipeline** for the checkout semantics.

### Gzip encoding

Raw JSON for 1000 files: ~150–200 KB. Compresses ~8–10× with gzip (JSON is
highly repetitive — identical keys like `.mca`, same hash length).

Stored as `manifests/*.json.gz` on both local and remote. ~20–25 KB each.

### Parent pointer

Advisory metadata only. Restore never reads it. Purposes:

- GUI can display lineage ("played on top of Jan 12")
- Detects branches (restore-then-play creates a parent that isn't the prior
  `current`)
- Future retention policies ("keep ancestors of current")

Dangling parent pointers after retention prunes the ancestor are fine — the
field becomes informational-only. Consumers must tolerate missing parents.

## Upload Pipeline

### Precondition

Server has exited. Session lock is held.

### Steps

1. **Scan.** Walk `./worlds/`, compute xxhash over each file (mtime-optimized
   scanner carries forward unchanged hashes from the prior manifest). Produce
   `new_map: map[path]hash`.

2. **Diff.** Compute `upload_set` = hashes in `new_map` not present on R2
   (checked via HEAD or `If-None-Match`). Files identical to any previously
   uploaded blob are skipped entirely.

3. **Blob upload (concurrent).** Worker pool of size N (default 16). Each
   worker:

   ```go
   for path in upload_set:
       data = os.ReadFile(worlds/path)
       hash = new_map[path]
       compressed = zstd.Encode(data, level=3)

       // Tee — one read of worlds/path, two destinations
       errgroup.Go(() -> local.PutBlob(hash, compressed))
       errgroup.Go(() -> remote.PutBlob(hash, compressed))
       wait
   ```

   Retry per destination, per file. Up to 5 attempts, exponential backoff
   (1 s base, 15 s cap). Matches current v2 retry policy.

4. **Write new manifest JSON.**

   ```
   new_manifest = {
       version: "2.1",
       timestamp: now(),
       parent: previous_current_timestamp,
       files: new_map,
   }
   ```

5. **Atomic commit — local first, remote second.**

   Local:
   - Write `./manifests/{ts}.json.gz` (new snapshot)
   - Overwrite `./manifests/current.json.gz` (atomic rename)
   - For each (path, hash) in `new_map`:
     `os.Link(objects/{hash}.blob.zst → backups/{ts}/worlds/{path})`
     (hardlinks — near-instant, zero bytes)

   Remote:
   - PUT `manifests/{ts}.json.gz` (new snapshot)
   - PUT `manifests/current.json.gz` (the commit — this is the linearization
     point for readers)

6. **Retention.** Prune manifests per policy on both local and remote.

7. **GC orphan blobs.** Mark-sweep remote; hardlink-refcount local. Runs after
   retention. Non-blocking — GC failure does not fail the session.

### Crash recovery

| Crash point | State | Next session |
|---|---|---|
| During blob upload | Some blobs present, some missing. Current manifest unchanged. | Re-diff, re-upload missing blobs. Idempotent. |
| After blobs, before manifest PUT | All blobs live. Current manifest unchanged. | Next diff finds nothing new. Session writes manifest cleanly. |
| After manifest PUT, before retention/GC | New world committed. Orphans possible. | Retention/GC runs next time. No data risk. |

The manifest PUT is the one atomic operation that makes the session "visible."
Before that point the world is the previous state. After: the new state.

### Per-file R2 ops

- v2: 3 ops per changed file (Put to staging + Copy to worlds + Copy to backup)
- v2.1: **1 op per changed file** (Put to `objects/`)

Plus session-total overhead of 2 manifest PUTs (current + snapshot). Constant.

## Download Pipeline

Fired on session start, after lock acquisition and before server launch.

### Steps

1. **Fetch remote `manifests/current.json.gz`**, decompress, parse.

2. **Diff against local `manifests/current.json.gz`.**
   - `download_set` = paths where local hash ≠ remote hash OR path new on remote
   - `delete_set` = paths present locally but absent in remote manifest

3. **Blob download (concurrent).** Worker pool, N=16:

   ```go
   for path in download_set:
       hash = remote_manifest[path]
       compressed = remote.GetBlob(hash)
       raw = zstd.Decode(compressed)
       if xxhash64(raw) != hash:
           return error
       // Tee — write local object + materialize worlds path
       errgroup.Go(() -> localFS.WriteFile(objects/{hash}.blob.zst, compressed))
       errgroup.Go(() -> localFS.WriteFile(worlds/{path}, raw))
       wait
   ```

   Same retry policy as upload.

4. **Ghost cleanup.** Delete every path in `delete_set` from `worlds/`.

5. **Manifest commit.** Overwrite local `manifests/current.json.gz` with remote
   content. Create `manifests/{ts}.json.gz` as a snapshot of downloaded state.

6. **Local hardlink backup** of the downloaded state:
   `backups/{ts}/worlds/**` hardlinked into `objects/`. Mirrors the upload
   backup step.

7. **Retention + GC.** Local only (remote retention is owner's responsibility
   at upload time).

### Crash recovery

| Crash point | State | Next session |
|---|---|---|
| During download | Some worlds/ files partially updated. Local manifest still old. | Re-diff — unfinished paths still differ. Retry. |
| After worlds/ material, before manifest commit | worlds/ matches target but local manifest is stale. | Next diff sees no difference — commits manifest cleanly. |
| After manifest commit | Session can proceed. | Nothing to recover. |

Ghost files left over from a crash: absent from local manifest after next
commit, cleaned on next diff pass.

## Restore Pipeline

Restore is a download against a **chosen manifest** rather than
`current.json.gz`. Reuses the same primitives.

### Input

User picks a timestamp from the retained manifest list (GUI/CLI).

### Preconditions

- Server not running
- Lock acquired

### Algorithm

```
1. GET/read manifests/{target_ts}.json.gz → target_map
2. Read local current manifest → local_map
3. For each path, hash in target_map:
     if local has objects/{hash}.blob.zst → decompress to worlds/{path}
     else → fetch remote objects/{hash}, verify, decompress, write
4. For each path in local worlds/ not in target_map: delete (ghost cleanup)
5. Write manifests/{new_ts}.json.gz = clone of target_map with:
     parent = target_ts
     timestamp = now()
6. Overwrite manifests/current.json.gz with the new clone
7. Release lock
```

### Semantics — checkout, not cherry-pick

Every file in `worlds/` after restore has exactly the bytes specified by the
target manifest. Files absent from the target are deleted. No merging, no
replay, no partial application.

The target manifest and any intermediate manifests (e.g. snapshots between
target and current) **remain untouched**. User can restore to a different
timestamp next; history is append-only, branches never overwrite each other.

### Network cost

- Common case (local objects/ still holds target blobs): zero network. Local
  decompress + copy only.
- Shallow-retention miss (target is older than local retention window): fetch
  missing blobs from R2. Same cost as a full delta download.

### Fallback — manual Explorer restore

`./backups/{ts}/worlds/` is a real directory tree (hardlinks present as files).

1. Open File Explorer
2. Navigate to `backups/2026-04-12T.../worlds/`
3. Copy contents into `worlds/`, overwrite when prompted

Works without Ritual. Ghost cleanup (files to delete) is not automatic in this
path — user handles manually, or next Ritual session reconciles at upload time.

## Retention

### Policy schema

```go
type RetentionPolicy struct {
    Last    int  // keep N most recent regardless
    Daily   int  // keep 1 per calendar day, N days
    Weekly  int  // keep 1 per ISO week, N weeks
    Monthly int  // keep 1 per calendar month, N months
}
```

Separate policies for local and remote. Local defaults shallower (e.g.
`Last: 2`), remote defaults deeper (e.g. `Last: 2, Weekly: 1, Monthly: 1`).

### Pure selection function

```go
func SelectRetained(refs []ManifestRef, cfg RetentionPolicy, now time.Time)
    (keep []ManifestRef, drop []ManifestRef)
```

Deterministic, no IO, no clock side-effects. Table-driven tests cover:

- Empty input
- Last-only policy
- Each tier alone
- Tier overlap (last 2 and weekly 1 both claim same snapshot)
- Sparse history (fewer snapshots than tier budget)
- Restore-then-play scenario (branch detection via parent pointer — does not
  affect selection, history stays linear by timestamp)

### Execution

```
1. List manifests/ → parse timestamps from filenames
2. keep, drop = SelectRetained(refs, cfg, now)
3. For each dropped manifest: delete file
4. Run GC
```

Manifest delete is cheap — one tiny JSON per retention pass.

## Garbage Collection

### Remote — mark-sweep

```go
liveHashes := map[string]struct{}{}
for each manifest in manifests/*.json.gz:
    data := Get(manifest_key)
    m := parse(data)
    for hash := range m.Files:
        liveHashes[hash] = struct{}{}

for blob in List(objects/):
    if blob.Hash in liveHashes: continue
    if time.Since(blob.Modified) < GCGracePeriod: continue
    remote.DeleteBlob(blob.Hash)
```

Grace period (default 1 h) protects in-flight uploads whose manifest PUT hasn't
landed yet. Eliminates a race without requiring a distributed lock.

Blob delete parallelized with 16-worker pool. Runs after remote retention.

### Local — hardlink refcount

```go
currentManifest := parseLocal(manifests/current.json.gz)
currentHashes := hashSet(currentManifest.Files)

for blob in os.ReadDir(./objects):
    nlinks := getNLinks(blob)    // NTFS GetFileInformationByHandle
    if nlinks > 1: continue                  // still linked from backups/{ts}/worlds/
    hash := parseHash(blob.Name)
    if hash in currentHashes: continue       // held by current worlds/ via blob identity
    os.Remove(./objects/blob)
```

Filesystem-level refcount; no manifest walking needed. `nlinks == 1` means only
`objects/` itself references the blob. Runs after local retention deletes
`backups/{ts}/` directories.

### Scheduling

- After every successful session upload (incremental)
- Periodic full sweep (daily), triggered from state machine idle handler or
  external cron

Failure in GC never fails the session — orphans linger until next run.

## Compression

### Algorithm

**zstd level 3** via `github.com/klauspost/compress/zstd`. Locked per-spec —
not runtime-configurable via user settings (would complicate dedup if clients
used different levels). Config knob exists for future algorithm upgrades,
defaulting to the locked choice.

### Measured ratios (from real 39 MB world)

| Category | Raw | Zstd-3 | Ratio |
|---|---|---|---|
| `.mca` | 31.5 MB | 6.1 MB | **19%** |
| `.sqlite` | 7.5 MB | 1.5 MB | **20%** |
| `.dat` | 546 KB | 402 KB | 74% |
| `.nbt` | 188 KB | 37 KB | 20% |
| `.json` | 28 KB | 3 KB | 10% |
| `.mcfunction` | 114 KB | 15 KB | 13% |
| Overall | 39 MB | ~8 MB | **~20%** |

### Where compression happens

- **On write** (`PutBlob`): adapter compresses `[]byte` before PUT to R2 / write
  to local FS
- **On read** (`GetBlob`): adapter decompresses after GET from R2 / read from
  local FS, verifies hash matches, returns raw bytes to caller

Port signature unchanged. Compression is an adapter-internal concern. Caller
always sees raw bytes.

### Not-applied-to list

- **Manifests** are gzipped (different algorithm choice — universal, stdlib,
  good for JSON). `compress/gzip` level 6.
- **`worlds/` directory** stays uncompressed. Minecraft reads raw files.

### CPU cost budget

400 MB session churn × zstd-3 @ ~500 MB/s on x86 ≈ ~1 s CPU total. Trivially
negligible next to ~30 s of network transfer.

## Concurrency Model

### Worker pool

`errgroup.Group` with `SetLimit(N)`. Default N = 16. Applies to:

- Blob uploads within an upload session
- Blob downloads within a download session
- Blob deletes within a GC sweep
- Remote manifest deletes within retention

### Per-file tee

Within a single worker, one file's bytes fan out to two destinations:

```go
data := os.ReadFile(path)         // one disk read
compressed := zstd.Encode(data)   // one compression

g, gctx := errgroup.WithContext(ctx)
g.Go(() -> local.PutBlob(gctx, hash, compressed))
g.Go(() -> remote.PutBlob(gctx, hash, compressed))
g.Wait()
```

Shared `[]byte` is race-free (read-only concurrent access in Go is safe). No
`io.Pipe`, no `io.MultiWriter`, no streaming machinery.

### Memory ceiling

Peak RAM during sync: `N_workers × avg_compressed_blob_size × 2`
(raw + compressed slices per worker). For 16 workers × 8 MB avg × 2 = ~256 MB
peak. Fits comfortably on any machine that runs a Minecraft server.

### Worker count tuning

Config-surfaced as `sync.workers` (default 16). Higher counts stop helping
once the pipe saturates; lower counts leave bandwidth on the table. Residential
internet + R2 empirically saturates around 8–32.

## Port Interfaces

### ObjectStore (new — replaces worlds-prefix usage of StorageRepository)

```go
type ObjectStore interface {
    PutBlob(ctx context.Context, hash string, data []byte) error
    GetBlob(ctx context.Context, hash string) ([]byte, error)
    HasBlob(ctx context.Context, hash string) (bool, error)
    DeleteBlob(ctx context.Context, hash string) error
    ListBlobs(ctx context.Context) iter.Seq2[BlobInfo, error]
}

type BlobInfo struct {
    Hash     string
    Size     int64
    Modified time.Time
}
```

Two implementations: `adapters.R2ObjectStore`, `adapters.FSObjectStore`. Both
handle zstd compression/decompression internally.

### ManifestStore (extends current manifest_store.go)

```go
type ManifestStore interface {
    Get(ctx context.Context, key string) (*domain.Manifest, error)
    Put(ctx context.Context, key string, m *domain.Manifest) error
    Delete(ctx context.Context, key string) error
    ListManifests(ctx context.Context) ([]domain.ManifestRef, error)
}

type ManifestRef struct {
    Key       string     // "manifests/2026-04-19T22-30-45Z.json.gz"
    Timestamp time.Time
    Size      int64
}
```

Key "current.json.gz" is a well-known alias for the live pointer.

### StorageRepository (retained, reduced surface)

Still used for `worlds/` directory reads during upload scanning and direct
file writes during download materialization. Unchanged `[]byte` signatures.

### Compile-time interface checks

Every adapter includes `var _ ports.ObjectStore = (*R2ObjectStore)(nil)` and
equivalent. Mocks also.

## Domain Model

### Manifest (replacing current single-section manifest)

```go
type Manifest struct {
    Timestamp time.Time           // RFC 3339 UTC
    Parent    string              // previous manifest filename (may be empty)
    Files     map[string]FileEntry
}

type FileEntry struct {
    Hash string  // hex xxhash64
    Size int64   // uncompressed byte size
}
```

v2 stores `FileEntry{Hash, Size}` already — reused verbatim. Size aids progress
calculation and backup estimates without extra I/O.

### Manifest with multiple sections (migration compatibility)

Existing v2 manifest nests `Worlds` and `Server` sections (per
`2026-04-14-unified-sync-design.md`). v2.1 keeps that structure. What changes:

- `ManifestVersion` stays `"2.0.0"` — project is alpha, free to evolve the
  schema without version bumps.
- Each section gains a `Files` map of `path → FileEntry{Hash, Size}` — reusing
  the existing v2 `FileEntry` type verbatim. `Parent` and per-section
  `Timestamp` live at section level so Worlds and Server retention are
  independent.
- Detection of v2.1 layout uses presence of `manifests/*.json.gz` in storage,
  not a schema version field.

Exact migration mechanics see **Migration** section.

## State Machine Integration

### New states

- **BlobUploading** — replaces current Staging + Committing phases. Single
  state that owns the worker pool uploading blobs to `objects/` on both sides.
- **ManifestCommitting** — writes new local/remote manifests + overwrites
  `current.json.gz`. Linearization point.
- **BackupMaterializing** — post-commit, builds `./backups/{ts}/worlds/`
  hardlink tree. Local only; remote backup is implicit in the manifest PUT.
- **Retaining** — runs retention policy on both sides, triggers GC.

### Upload flow

```
Preparing → Locking → Running → Exiting → BlobUploading
                                            ↓
                                ManifestCommitting
                                            ↓
                                BackupMaterializing
                                            ↓
                                       Retaining
                                            ↓
                                       Unlocking
```

Failure routes go to `Failed` as in v2. Each state emits
`Started/Progress/Finished/Failed` events via EventBus (per
`feedback_sync_observability`).

### Download flow

```
Preparing → Locking → BlobDownloading → ManifestCommitting
                            ↓                  ↓
                        GhostCleaning    BackupMaterializing
                                                ↓
                                           Retaining
                                                ↓
                                            Running
```

## Events

Per-stage lifecycle (started / progress / finished / failed) via `ports.EventBus`.
Event types colocated with emitters (per `28d88cc refactor(events)`).

### New events

- `BlobUploadStartedInfo { Files int, TotalBytes int64 }`
- `BlobUploadProgressInfo { File string, FilesDone, FilesTotal int, BytesDone, BytesTotal int64 }`
- `BlobUploadFinishedInfo { DurationMs int64 }`
- `BlobUploadFailedInfo { File, Err string }`
- Mirrored for Download, Restore, Backup, Retention, GC.

GUI + CLI stdout both subscribe to these. No per-R2-op events (too noisy) —
events are per-file.

## Test Strategy

Tests document behavior. Every test < 1 s. `t.Context()` with `WithTimeout` in
every test. No mocked databases / filesystems at boundaries where real IO is
fast (< 100 ms) — use `t.TempDir()`.

### Pure-function tests (exhaustive table-driven)

- **DiffEngine** — reuses v2's pure function
- **SelectRetained** — every tier combination, tier overlap, sparse history
- **Manifest JSON roundtrip** — v2 manifest readable by v2.1 parser, v2.1
  manifest readable by v2 parser (forward/back compat)
- **Hash round-trip through zstd** — raw bytes → compress → decompress →
  hash matches

### Adapter integration tests

- **R2ObjectStore** — PutBlob then GetBlob returns identical raw bytes; integrity
  verify catches corruption (injected MITM)
- **FSObjectStore** — same, against a real temp dir
- **ManifestStore** — write + list + get roundtrip; timestamp parsing from
  filenames; gzipped content
- **Compression ratio sanity** — a known `.mca` fixture compresses to the
  expected byte size ± 5 %

### Service tests (mock-based)

- **UploadService** — happy path, each state's failure mode, retry exhaustion,
  empty diff
- **DownloadService** — same set
- **RestoreService** — local-only path (no network fetches), mixed path, empty
  target diff
- **RetentionService** — correct drop set produced, manifest deletes batched,
  GC skipped if any retained manifest fails to load

### End-to-end integration test

- Spawn two temp `./` structures (host A, host B)
- Run upload on A, download on B, verify B's `worlds/` matches A's
- Modify A, upload, download on B, verify propagation
- Delete files on A, upload, verify B deletes them (ghost cleanup)
- Restore from 2 sessions ago on A, verify worlds match target
- Retention ages out old snapshots correctly

### Benchmarks (informational, not blocking)

- Upload 400 MB churn at simulated 20 / 40 / 80 Mbps through a rate-limited
  test harness
- Verify worker-count scaling curve (8, 16, 32, 64)
- Track compression CPU time to catch regressions

### Compile-time checks

`var _ ports.ObjectStore = (*R2ObjectStore)(nil)` on every adapter and mock.

## Migration from v2

### Layout detection (not schema version)

- v2 remote has `worlds/` + `sync/` prefixes populated, no `manifests/` or
  `objects/` prefix.
- First v2.1 session lists remote: if `manifests/current.json.gz` is absent,
  treat as first run — full scan, full compress, full upload to `objects/`.
  Same code path as `FullWorldScanner` when xxhash_map is empty.
- After first v2.1 commit, old v2 remote layout becomes obsolete.
- `ManifestVersion` stays `"2.0.0"` throughout — no bump needed while alpha.

### Cleanup of v2 remote state

After successful first v2.1 upload + backup materialization:

- Delete `sync/*` remote prefix (staging dirs, no longer used)
- Delete `worlds/*` remote prefix (replaced by `objects/` + manifest)
- Delete `backups/*` v2 format (replaced by `manifests/*.json.gz`)

Done as a one-shot migration step in the first v2.1 session. Runs after the
first v2.1 manifest commits cleanly — so if migration fails, next session
retries (the v2.1 commit already succeeded, world is safe).

### Mixed-version prevention

`RitualUpdater` already enforces minimum Ritual binary version via manifest.
First v2.1 release bumps the minimum binary version — all clients auto-update
before sync. No mixed scenario possible.

### Backwards reading

v2.1 client reading a v2 remote: detects absent `manifests/` prefix, treats as
"first run" (full upload). v2 client reading v2.1 remote: never happens —
binary auto-update gates it.

## Performance Projections

(400 MB per session), zstd-3 compression (measured ~5× reduction), residential
bandwidth.

| Operation | v2 @ 40 Mbps | v2.1 @ 40 Mbps | v2 @ 20 Mbps | v2.1 @ 20 Mbps |
|---|---|---|---|---|
| Incremental upload (400 MB churn) | ~10 min | **~30 s** | ~15 min | **~45 s** |
| R2 backup stage | ~10 min | **<1 s** | ~10 min | **<1 s** |
| Local backup stage | ~30 s | **~1 s** | ~30 s | **~1 s** |
| Incremental download (400 MB churn) | ~3 min | **~35 s** | ~5 min | **~45 s** |
| Full download (1 GB new host) | ~10 min | **~80 s** | ~15 min | **~3 min** |

## Acceptance Criteria

### Must have (blocks release)

- [ ] Upload at 40 Mbps, 400 MB churn, completes in < 90 s end-to-end
- [ ] R2 backup stage (manifest PUT + snapshot PUT) completes in < 5 s for any
      world size
- [ ] Blob integrity verification catches corrupted/truncated downloads
      (injected-fault test passes)
- [ ] Concurrent worker pool (16 default) configurable, tested at 1, 8, 16, 32
- [ ] Content-addressed blob store deduplicates across snapshots — identical
      file referenced by 10 manifests produces 1 blob on disk
- [ ] Retention policy: last / daily / weekly / monthly tiers all honored,
      tier overlap deduplicated
- [ ] GC never deletes a blob referenced by any retained manifest
- [ ] GC grace period (default 1 h) protects in-flight uploads
- [ ] Restore to any retained snapshot produces a `worlds/` directory exactly
      matching that snapshot (file-by-file hash verify)
- [ ] Self-service Explorer restore works from `backups/{ts}/worlds/`
- [ ] Migration from v2: first v2.1 session on a v2 bucket completes full
      upload + cleans old prefixes
- [ ] Streamer package stays deleted. No new tar / gzip streaming code.
- [ ] Compile-time interface checks on every adapter + mock
- [ ] All unit tests run in < 1 s each; test suite wall clock < 30 s
- [ ] Zero data corruption under crash injection at each pipeline stage
      boundary

### Should have (polish, not blocking)

- [ ] Parent pointer populated on every new manifest
- [ ] Benchmarks for worker-count scaling committed + baseline saved
- [ ] Per-stage progress events emitted for GUI consumption

### Must not

- [ ] Must not reintroduce `io.Reader` / `io.Writer` ports on StorageRepository
- [ ] Must not reintroduce tar / gzip streaming in the sync path
- [ ] Must not store uncompressed blobs on R2 or local objectstore
- [ ] Must not require tar-aware code anywhere outside the legacy v2 migration
      cleanup (to be removed after migration)
- [ ] Must not add per-blob R2 CopyObject calls (the whole point is to kill
      them)
- [ ] Must not let GC delete an in-flight blob (grace period + live-set check)
- [ ] Must not increase RAM footprint above ~512 MB peak during sync

  restart? Initial assumption: restart only (config reload is out of scope).
