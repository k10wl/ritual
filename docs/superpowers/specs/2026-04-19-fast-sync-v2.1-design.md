## Motivation

Delta sync v2 gave us per-file granularity and resumability, but sync + backup
stages together take 20+ minutes on a 1 GB Minecraft world at residential
bandwidth. Two reasons:

1. **Sequential per-file I/O.** Single worker sends one R2 round-trip at a
   time. Latency × file count = wall clock. At 40 Mbps with 500 changed files,
   the pipe sits idle ~50% of the time waiting for R2 responses.
2. **Per-file Copy storm on backup.** Each retained backup invokes
   `CopyObject(worlds/path → backups/{ts}/worlds/path)` for every file.
   Measured production: ~10 minutes just to create one R2 backup.

Separately, the v2 design had interface problems that surfaced during deeper
review:

3. **Opaque pipeline.** The v2 sync is a single procedure. v2.1 exposes four
   named, direction-preserving verbs so session flows, live-ticker flows,
   restore flows, and config-only edits all compose from the same primitives.
4. **`[]byte` end-to-end.** Minecraft `.mca` files reach ~100 MB; materialised
   `[]byte` blows memory under parallel workers. The storage port streams.
5. **ACID was handwaved.** v2.1 formalises per-verb atomicity, consistency,
   isolation, durability — including post-stop, live-ticker, and amend cases.
6. **R2 failure modes are undocumented.** Cloudflare R2 docs (retrieved
   2026-04-20) do not warrant PutObject partial-write behaviour, CopyObject
   failure-destination state, or CAS linearizability. Spec uses conditional-PUT
   (`If-Match`) and post-PUT verify as documented mitigation against
   undocumented edges.

Three speedups remain from the original v2.1 draft:

- **Content-addressed blob store** — every file identity is its xxhash;
  manifests are JSON pointers into a shared blob pool.
- **Concurrent workers** — 10 parallel uploads/downloads fill the bandwidth
  pipe during R2 round-trip waits (POC measured 10 saturates 20 Mbps → 1 Gbps).
- **Zstd compression on blobs** — measured ~5× reduction on a real 39 MB MCA-
  heavy world.

Together: **20 min → ~30 s at 40 Mbps**, **30 min → ~45 s at 20 Mbps**.

## Goals

- Upload a 1 GB world with medium session churn in < 1 min at 40 Mbps.
- Live-ticker commit completes local snapshot in < 10 s on 1 GB worlds
  (autosave already disabled via boot-time `save-off`; each tick fires
  `save-all flush` before walking).
- Restore any retained snapshot via `ritual restore` or self-service Explorer
  (local-side only).
- Storage local + remote deduplicated across retained snapshots.
- Zero corruption risk — manifest PUT is the world's source of truth, ACID
  guarantees formalised per verb.
- Interface is expressed as four composable verbs; flows are compositions,
  not forks.
- Streaming throughout — no full-file `[]byte` buffering under normal load.

## Non-goals

- Intra-file resumable uploads (32 MB file retries from zero — acceptable at
  Minecraft file sizes).
- Branch/merge semantics (linear per-world timeline, locks enforce single-
  writer).
- Remote self-service restore without tooling (local side stays Explorer-
  browsable; remote needs Ritual or a small script).
- Runtime fallback to binary defaults when manifest missing — `ritual init`
  seeds the first manifest from `DefaultTargets`; runtime reads scope from
  the manifest only. Empty-remote sessions fail with clear error.

## Design Doctrine

> **Motto: NOT WRITTEN CODE IS BEST CODE.**

Every line of code is a liability. Every line carries defect risk,
review cost, and comprehension tax — forever. Before writing, ask what
can be deleted, collapsed, or never added. The cheapest bug is the one
in code that never existed. LOC budget is always negative.

### If statements hoard bugs

`if` is the wrong primitive for control flow. Conditionals hide the
state machine inside a function body and multiply the combinatorial
test surface with every branch added. Every `if` is a promise that the
two paths stay in sync forever — a promise no codebase keeps. `IF IF IF
FI FI FI` is not a design; it is a trap.

### Flow is a story, told as composed units

Application flow is narrative. A good story reads as a sequence of
named acts, each self-contained, each calling the next. Bad stories
are a recursive tangle of "if this then if that else if otherwise".
The story IS the call graph — readable at the composition root,
linearly, top to bottom.

**Prefer calling to branching.** Polymorphic dispatch through GoF
pattern slots expresses variance at the type level, where it is
inspectable, nameable, and testable without branch-coverage gymnastics.

| Wrong (if-driven) | Right (call-driven) |
|---|---|
| `if mode == remote { ... } else { ... }` | Strategy injected at composition root |
| `if feature { extra() }` | Decorator wrapping the port |
| `if retry { ... }` | Chain of Responsibility / Retry decorator |
| `if state == X { ... }` | State pattern, dispatch on state value |
| `if x != nil { use(x) } else { default() }` | Null Object — no nil, no branch |
| `if opts.Amend != "" { amend() } else { fresh() }` | Committer holds a CommitStrategy |
| `if retention.dropped > 0 { gc() }` | Structural chain: `push → retention → gc` |
| Nested `if` ladder for error classification | Table-driven `map[errClass]action` |

**No hidden state inside functions.** No package globals, no
`sync.Once` in business logic, no lazy-init on first call, no
memoization caches tucked inside helpers. State lives on a struct,
wired at the composition root, mutated through explicit setters. The
call site is the only place flow is decided.

**Sequence of calls IS the control flow.** `A(); B(); C()` is a story.
`if ok := A(); ok { if ok := B(); ok { C() } }` is a bug farm. Early
return on sentinel error; the happy path stays linear.

### Pattern vocabulary (use when the slot is real, never speculative)

| Pattern | Slot it names |
|---|---|
| Strategy | Pluggable variance at a single call site |
| Decorator | Cross-cutting concern wrapping a port (observability, compression, retry, fence) |
| Chain of Responsibility | Ordered pipeline of steps, each passes or short-circuits |
| Command | Self-contained callable with a named intent (e.g. each of the four verbs) |
| State | Behaviour variance driven by a state value; caller dispatches on state |
| Template Method | Fixed skeleton with plug-in hook points |
| Null Object | Default implementation that makes nil-checks impossible |
| Visitor | Type-switch replaced by polymorphic dispatch (e.g. Target matchers) |
| Composite | Uniform treatment of single + group (e.g. `CadencePolicy` OR semantics) |

Pattern slots are imported only when the code needs them. Every named
slot must answer a concrete question in the current design; speculative
slots are themselves liabilities.

### Enforcement

- No `bool` parameters on exported APIs — each bool splits one function
  into two Strategy impls; make the split explicit in the type system.
- No `nil`-checks on injected ports — composition root supplies Null
  Object or the call is invalid; never both.
- No `if opts.X != nil { X() }` — caller selects the X-flavoured slot;
  verb body stays linear.
- Tests assert the call graph + output, not which branch was taken.
  Branch-coverage tests are a smell: the branch should have been a
  polymorphic call.
- New file budget: ≤ 150 LOC including tests. Exceed = split by role,
  not by line count.
- Before writing new code, try to delete something first.

### Doctrine precedence

This section outranks every implementation detail that follows. If a
later section describes an `if`-based flow, it is wrong — rewrite as
composition before implementing. If an acceptance criterion tests a
branch, rewrite the acceptance criterion before writing the test.

## Testing Doctrine

> **Every module is a story. Every story is testable in isolation.
> Every test is a user story the reader can follow top to bottom.**

**Scope**: this section states universal rules that apply to every
test in this codebase. The later *Test Strategy* section lists which
scenarios (per-verb unit, integration, performance) are required for
v2.1 specifically. Rules here outrank any scenario inventory there —
if the two disagree, the doctrine wins.

Tests are not verification afterthoughts — they are the specification
in executable form. A module that is hard to test in isolation has the
wrong shape; fix the module, not the test. The test suite is the world
the codebase builds; each module contributes a story; the stories
compose under business rules into a single coherent narrative.

### Canonical reference

[`internal/app/ritual_integration_test.go`](../../../internal/app/ritual_integration_test.go)
is the load-bearing example. Its header comment is the operative
ruleset for every new test in this codebase. When in doubt, read that
file and follow its pattern.

### Rules (binding)

1. **No comments in test bodies.** Code self-documents through function
   names, variable names, and helper names. If a line needs a comment,
   the name is wrong — rename until the comment is redundant.
2. **Variable names carry meaning.** `ritual` not `env`, `server` not
   `srv`, `retryServer` not `srv2`. Unambiguous in a stack trace, in a
   diff, in a grep result.
3. **Assertion messages are the sole documentation.** Verbose, explain
   scenario context — not a restatement of the check. Three failure
   signals: test name → assertion message → expected vs actual. Every
   message non-empty. Bare assertions forbidden.
4. **Test function names read as user stories.**
   `TestIntegration_PlayedAndExitClean_ChangesUploadedAndBackedUp`, not
   `TestIntegration_Case8`.
5. **Flat arrange-act-assert** — visible in one scroll. Helpers hide
   plumbing, never intent. No nested setup that swallows the story's
   opening line.
6. **No table-driven tests.** Each scenario is its own function. Tables
   hide plot beats behind an index.
7. **Timeouts + ceiling**: every test <1 s wall-clock; every `go test`
   passes `-timeout`; suite wall-clock <30 s; context from
   `t.Context() + WithTimeout`, never `context.Background()`.

### Story model

- **Each module tells one story.** Pull tells a pull story, Apply tells
  an apply story, Committer tells a commit story. Module tests
  enumerate every plot beat: happy path, edge cases, crash points,
  recovery branches.
- **Stories combine into a world.** User-story tests in `app_test`
  (`ritual_integration_test.go`, `ritual_test.go`) show composition —
  Pull → Apply → Run → Commit → Push end-to-end, including failure
  interleavings. These are user stories. Do NOT call them "glue
  tests", "wiring tests", or "integration glue" — that framing
  degrades them into scaffolding. They are the authoritative
  description of user-visible behavior.
- **Business rules dictate world shape.** ACID invariants per verb,
  lock discipline, retention policy — these are the laws the world
  obeys. Every test observes that the laws held on one run.
- **Stories adjust and compose.** Adding a feature = adding a story,
  not branching an existing one. Rewriting a feature = rewriting the
  story. Stories never share bodies.

### Testability is a design constraint

A module that needs live FS, real R2, or running Minecraft to exercise
has wrong ports. Fix the module:

- Inject every dependency through a port.
- Supply fakes/mocks/decorators at the composition root.
- Pure functions for anything pure-able (retention policy, manifest
  validation, classifier tables).
- Integration tests use real FS + `observed` decorator + scripted
  storage for deterministic failure injection — never live R2.

### Per-verb story requirement

Each of the four verbs (Pull, Apply, Commit, Push) owns a dedicated
test file whose function names enumerate its ACID story. STORAGE-n
stories inherit this rule. Acceptance criteria phrased as "V1 tests
still green" or "tests pass" are insufficient — acceptance must name
the stories added or amended.

### Test pyramid

Bottom-up build order; top-down narrative order:

| Layer | Scope | Port-level isolation | Story form |
|---|---|---|---|
| Primitives | `FSRepository`, `R2Repository` streaming | tempdir / `httptest` mock | "GetStream returns body and size" |
| Decorators | `ObservedStorage`, `CompressingStorage` | fake inner storage | "GetStream emits Started/Read/Finished in order" |
| Domain types | `Ref`, `RefID`, `Object` | pure, no IO | "RefID round-trips across JSON and filename" |
| Verbs | `Puller`, `Applier`, `Committer`, `Pusher` | two `FSRepository`s rooted at tempdirs (local + remote-stand-in) | "Applier writes every file declared by ref" |
| **User stories** | end-to-end sessions through composed stack | same FS-backed stack (dev == test == CI) | "operator plays a patch session and exits clean" |

Top of the pyramid = **user stories**. They name operator intent, not
components. Build bottom-up (primitives first) so the top stories run
against verified primitives; read top-down (user story first) when
reviewing what the system does.

Acceptance per feature names a user story, not a module test. Module
tests exist to give the user story a foundation that isn't flaky.

User-story files are `internal/app/ritual_integration_test.go` and
`internal/app/ritual_test.go`. The canonical authoring rules live in
the header of `ritual_integration_test.go`. These files own the
end-to-end shape of ritual. They are NOT integration glue, wiring
tests, or composition-root scratch — they are the user-facing
specification.

### Doctrine precedence

Testing doctrine outranks implementation expedience. A module that
cannot be tested per these rules has the wrong shape. Reshape the
module; never lower the testing bar. Tests that violate these rules
block merge.

## On-disk / on-R2 Layout

### User-data root (local)

```
%APPDATA%/ritual/                        user-data root — directly tool-owned
├── objects/{hash}                       zstd-compressed blob; bare hash name
├── refs/{refid}.json                    uncompressed JSON (see Ref Format)
├── lock                                 local session lock state
├── worlds/**                            tracked subtree — Minecraft worlds
├── server/**                            tracked subtree — Minecraft server
└── settings.json                        host-local prefs (server runtime,
                                         retention, requirements);
                                         NOT tracked, NOT synced;
                                         binary defaults provide baseline
```

Rationale for flatness: the user-data root is already tool-owned. A nested
`.ritual/` dir would be redundant — git's dotdir convention exists to
separate tool state from user files, and ritual has no user files to
separate from. Every subdirectory here belongs to ritual.

### Remote (R2)

```
{bucket}/{prefix}/
├── objects/{hash}                       zstd-compressed blob; bare hash name
├── refs/{refid}.json                    uncompressed JSON
└── lock                                 session lock object
```

Flat. No `worlds/`, `server/`, `staging/`, `backups/` prefixes on remote —
everything is either a content-addressed blob or a timestamped ref.
Instance-specific subtree structure exists ONLY inside ref JSON.

### HEAD is derived, not a file

`HEAD = max(parseRefID(key)) for key in List("refs/")`

No `HEAD.json` pointer file. Reasons:

- **Single PUT per push** — atomic per R2 object.
- **Zero window where HEAD is missing or corrupted** — HEAD is a computation,
  not a stored value.
- **No "stranded push" recovery pass** — no orphan pointer state possible.
- **No duplicate-archive retention bug** — no separate HEAD to get confused
  with its archive.

Read-HEAD cost = 1 LIST + 1 GET. Trade: cannot pin HEAD to an older manifest.
Rollback becomes a fresh commit of restored state, matching content-addressed
immutable-history semantics (see [Rollback](#rollback) below).

### Alternatives considered

| Alternative | Why rejected |
|---|---|
| `HEAD.json` pointer file | +1 PUT per push (2-object transaction with no R2-warranted atomicity). Introduces stranded-pointer recovery state. Revives the retention duplicate-archive bug (see [HEAD-duplicate concern](#head-duplicate-concern-does-not-apply)). |
| Alias key `refs/current.json` overwritten per push | Same +1 PUT. Loses immutability of the "current" slot — any observer reading mid-push sees torn bytes or stale content. |
| Parent-chain walk from a bootstrap pointer | Still needs a bootstrap pointer (HEAD.json reincarnated). O(N) GETs to find HEAD vs 1 LIST. Strictly worse. |
| R2 object versioning for latest-object semantics | Non-portable (locks the design to R2-specific features). Cost tier unclear. FSRepository has no equivalent — breaks port symmetry. |

Retention caps manifest count at `Last + Daily + Weekly + Monthly` (~19
default). LIST returns one unpaginated page in ~50–200 ms cold. GET saved
by a pointer file is ~1 request of the same magnitude. Derived HEAD wins on
complexity, not latency — the latency delta is within noise.

### Rollback

Rollback is not a new verb; it is a composition of existing verbs:

```
operator picks T_old from LIST(refs/)
pull(T_old)                   ← fetch manifest + any missing blobs
apply(T_old)                  ← materialise old state into instance/
commit(Parent=T_old) → M_new  ← new manifest, objects map identical to T_old
push(M_new)                   ← M_new.timestamp > T_old ⇒ new HEAD
```

Blob uploads during the rollback push are zero: every hash in `M_new.objects`
already exists remotely (they were uploaded when T_old was pushed). Only the
manifest PUT travels the wire. Cheap, immutable, linear-history-preserving.

Offline variant: when remote is unreachable, local HEAD is derived the same
way from `.ritual/refs/*.json` (`max(timestamp)`). Commit stacks local
drafts; push on reconnect. No separate offline-HEAD concept required.

### Settings file

`settings.json` at the user-data root holds host-local runtime prefs:
server runtime (port, memory, start script), retention policies (local +
remote), host requirements (min RAM / disk / Java version).

```go
type Settings struct {
    Server       Server       `json:"server"`
    Retention    Retention    `json:"retention"`
    Requirements Requirements `json:"requirements"`
}

type Server struct {
    Port        int    `json:"port"`
    Memory      int    `json:"memory"`
    StartScript string `json:"start_script,omitempty"`
}

type Retention struct {
    Local  RetentionRules `json:"local"`
    Remote RetentionRules `json:"remote"`
}

type Requirements struct {
    MinRAMMB       int `json:"min_ram_mb,omitempty"`
    MinDiskMB      int `json:"min_disk_mb,omitempty"`
    MinJavaVersion int `json:"min_java_version,omitempty"`
}
```

`DefaultSettings()`:

- `Server`: `{Port: 25565, Memory: 4096}`
- `Retention.Local`: `{Last: 2}`
- `Retention.Remote`: `{Last: 2, Daily: 7, Weekly: 4, Monthly: 6}`
- `Requirements`: zero-valued; getters (`GetMinRAMMB` / `GetMinDiskMB` /
  `GetMinJavaVersion`) resolve zero to `config.DefaultMin*`.

- **NOT tracked** — never appears in a ref's `objects`.
- **NOT synced** — host-specific.
- Binary compiled-in defaults apply when absent.

Keeping host prefs out of the tracked tree prevents cross-host config drift
via sync.

## Ref Format

A **Ref** is a content-addressed snapshot reference. Each push produces a
new ref at `refs/{refid}.json`. One file = one complete snapshot. Self-
contained: restore reads exactly one ref, no history traversal.

```json
{
  "timestamp":      "2026-04-20T15-35-38.123Z",
  "parent":         "2026-04-20T14-00-00.000Z",
  "ritual_version": "2.1.0",
  "targets": [
    "worlds/**",
    "server/**",
    "server/server.properties",
    "server/mods/**"
  ],
  "objects": {
    "worlds/world/region/r.0.0.mca": { "hash": "a1b2c3d4e5f67890", "size": 419430400 },
    "worlds/world/level.dat":         { "hash": "1234567890abcdef", "size": 2048 },
    "server/server.jar":              { "hash": "fedcba0987654321", "size": 47185920 },
    "server/plugins/worldedit.jar":   { "hash": "9876abcd5432efgh", "size": 3145728 }
  }
}
```

### Fields

- `timestamp` — `RefID`: `YYYY-MM-DDTHH-MM-SS.mmmZ`, UTC, millisecond
  precision, 24 chars. Dash form is canonical in both JSON and filename
  (Windows NTFS forbids `:` in filenames); no translation layer. Example
  filename: `refs/2026-04-20T15-35-38.123Z.json`. Lexical order ==
  chronological order; `HEAD = max(List("refs/"))`. Millisecond resolution
  is collision-proof at realistic human / live-ticker cadence (seconds to
  minutes between commits).
- `parent` — prior ref's `RefID`. Advisory only; does not gate restore.
  Empty string on the init ref.
- `ritual_version` — binary version that wrote this ref. Updater compares
  `HEAD.ritual_version != config.AppVersion` on session start → self-update.
  Only-one-live-version posture: comparison is strict inequality, not
  ordering. Bumps when any session with the new binary pushes a ref.
- `targets` — allowlist globs. First-class field. Seeded from
  `DefaultTargets` on `ritual init`; thereafter carried forward or amended
  via CLI/GUI (`ritual target add/remove`, patch flow). Binary defaults are
  an init-time seed, NOT a runtime fallback — once a ref exists, it owns
  the truth.
- `objects` — flat map; key = root-relative slash path inside tracked
  subtrees (`worlds/*` or `server/*`); value = `Object{Hash, Size}`.
  Hash is hex xxhash64 of raw (pre-compression) file bytes. Size is the
  **raw** (pre-compression) byte count — used for plan totals, disk-space
  preflight, and progress accounting. Compressed sizes are derived at
  pull-plan time via `List("objects/")` and are not persisted.

### Go types

```go
type Ref struct {
    Timestamp     RefID             `json:"timestamp"`
    Parent        RefID             `json:"parent,omitempty"`
    RitualVersion string            `json:"ritual_version"`
    Targets       []string          `json:"targets"`
    Objects       map[string]Object `json:"objects"`
}

type Object struct {
    Hash string `json:"hash"`
    Size int64  `json:"size"` // raw, pre-compression
}

type RefID string // canonical form: "2006-01-02T15-04-05.000Z" (24 chars, UTC, ms)
```

All types live in a single file `internal/core/domain/ref.go`.

### Out-of-ref residence

Fields that lived on v2's `Manifest` but have no place in a content-
addressed ref:

| Former manifest field | v2.1 home | Notes |
|---|---|---|
| `ManifestVersion` | (deleted) | Alpha — only one live version maintained, no schema bumps |
| `LockedBy`, `UpdatedAt`, `HeartbeatAt` | `{prefix}/lock` object | See §Lock Discipline (sessionId, acquiredAt, heartbeatAt, expiresAt) |
| `Lease.HeartbeatInterval`, `Lease.TTL` | `lock.DefaultHeartbeatInterval` (1 min) + `lock.DefaultTTLMultiplier` (5.2) on the `Locker` struct | TTL derived as `interval × 5.2` at write time; persisted in lock's `expiresAt` |
| `MinRAMMB`, `MinDiskMB`, `MinJavaVersion` | `settings.json` → `Requirements.*` (zero → `config.DefaultMin*` via getters) | Host-local; no cross-host admin enforcement |
| `Server.StartScript` | `settings.json` → `Server.StartScript` | Host-local |
| `RemoteRetention` | `settings.json` → `Retention.Remote` (defaults from `DefaultSettings()`) | Binary defaults: `Last:2, Daily:7, Weekly:4, Monthly:6` (remote); `Last:2` (local, via `Retention.Local`) |
| `Worlds` / `Server` split | collapsed into `Targets` + `Objects` | Glob allowlist decides scope |
| `SyncState.XXHashSyncAt` | ref filename timestamp | Per-ref, not per-subtree |
| `FileEntry.Size` (raw) | `Object.Size` (raw, unchanged) | Semantics preserved |

Everything operational moved out. The ref is a pure content-addressed
snapshot.

### Self-contained

Each ref describes a complete snapshot. Restore reads exactly one ref and
reconstructs full state. No history traversal. Deleting one ref never
breaks another.

### Allowlist targets, not denylist

Minecraft + mods write files to arbitrary paths: `logs/`, `crash-reports/`,
mod-specific caches, temp jars. Enumerating ignores is whack-a-mole.
Enumerating what to sync is finite and predictable.

`DefaultTargets` covers standard Paper/Spigot/Vanilla and ships with the
binary as an **init-time seed only**:

```go
var DefaultTargets = []string{
    "worlds/**",
    "server/server.jar",
    "server/server.properties",
    "server/eula.txt",
    "server/bukkit.yml", "server/spigot.yml", "server/paper.yml",
    "server/plugins/**",
    "server/mods/**",
    "server/config/**",
    "server/ops.json", "server/whitelist.json", "server/banned-*.json",
}
```

`ritual init` writes these into the first manifest. Subsequent sessions
read scope from the manifest, never from `DefaultTargets` — upgrading the
binary does NOT re-inject defaults into existing worlds.

Operators amend scope via CLI/GUI (`ritual target add/remove`) — each edit
produces a new manifest (config-only commit, patch flow) so the scope
travels with history. No on-disk `ritual.json` config; targets live in the
manifest. Binary releases ship only code; scope changes are data edits.

### Glob syntax

Doublestar semantics (requires the `github.com/bmatcuk/doublestar/v4`
dependency — stdlib `path.Match` rejects `**`):

- `**` matches any number of path segments including `/` (`worlds/**`
  matches `worlds/a`, `worlds/a/b/c.dat`).
- `*` matches a single path segment, no `/` (`server/*.json` matches
  `server/ops.json`, not `server/plugins/foo.json`).
- `?` matches one character.
- Patterns are root-relative, slash-separated, case-sensitive on remote
  keys and case-insensitive on Windows disk (normalised at walk time).

Invalid patterns rejected at `validate(m)` with the offending glob quoted.

### No compression on manifests

Manifests are ~20 KB uncompressed JSON. Not worth the decompression step or
the format coupling. Stays plain `.json`.

### Parent pointer usage

Advisory metadata only:
- GUI can display lineage ("played on top of Jan 12").
- Detects branches (restore-then-play creates a parent that isn't the prior
  HEAD).
- Does NOT gate restore. Each manifest is independently restorable.

Dangling parent pointers after retention prunes the ancestor are fine — the
field becomes informational only. Consumers tolerate missing parents.

## Content-Addressed Blobs

### Blob identity

```
hash = xxhash64(raw_file_bytes)    // deterministic, fast, non-crypto
key  = objects/{hex(hash)}         // bare hash, no extension
```

Hash is always computed over **raw** (pre-compression) content. Storage
format is zstd-compressed. This keeps identity stable regardless of
compression settings and lets us verify integrity on download by
decompressing and re-hashing.

xxhash64 collision risk for ~1000 files × 10-year worlds: negligible
(< 10⁻¹⁵ by birthday bound).

### Blob immutability

Blobs are write-once. `PutBlob(hash, data)` for an existing key is a no-op
(or a conditional `If-None-Match: *` PUT to avoid redundant upload).
Deterministic zstd-3 output means two clients with identical raw bytes
converge on the same compressed blob.

### Integrity verification on read

Performed in the `CompressingStorage` decorator. See
[Integrity Model](#integrity-model) for invariants, check points, and
recovery.

### No `.ritual.tmp` for blob writes

Blob names are self-verifying (filename IS the hash of expected contents).
A partial write leaves a file whose actual xxhash ≠ filename, detected at
next read. Recovery = delete + refetch. No `.ritual.tmp`+rename needed.

### Uniform zstd on every object

Every blob in `objects/` is zstd-compressed. No size threshold, no
extension skip, no format marker byte. Consistency eliminates a branch in
both write and read paths and collapses the format-detection surface.
Measured overhead on tiny payloads (4 B `session.lock` → ~10 B on disk) is
bytes per file; invisible against the LoC and failure-mode cost of a
size-discriminating path.

## Integrity Model

Single source of truth for "what must match what, where it is checked,
and how a mismatch heals." Every verb's ACID section points here rather
than restating.

### Invariants (per manifest M)

```
∀ (path, hash) ∈ M.objects : xxhash(instance/<path>) == hash
∀ hash ∈ M.objects.values  : xxhash(decompress(objects/{hash})) == hash
parse(refs/{M.ts}.json) validates against schema
```

### Check points + recovery

| Layer | Verifies | On fail |
|---|---|---|
| CompressingStorage.GetStream | blob decompressed xxhash == key | error "blob integrity mismatch" → caller deletes + refetches |
| Apply step 3 skip gate | disk file xxhash == manifest hash | rewrite file from blob |
| Apply step 3 write | streamed xxhash == manifest hash during write | error surfaces, tmp discarded, retry on next apply |
| Commit walk | raw bytes → xxhash → blob name | natural (hash IS the name) |
| Manifest read (pull, amend load, HEAD derive) | JSON parse + schema validate | delete local file → refetch (pull) or re-commit (commit) |
| Blob partial write | filename ≠ actual xxhash | next read catches, delete + refetch |
| [should-have] Startup sample-verify | random 1% of local blobs | delete corrupt blob, next pull refetches |

Canonical verify path:

```go
compressed := storage.GetStream(ctx, "objects/"+hash)
defer compressed.Close()
dec := zstd.NewReader(compressed)
// pipe through xxhash while copying — assert at EOF
if actualHash != hash {
    return errors.New("blob integrity mismatch")
}
```

### Recovery principle

Every integrity failure heals through re-execution of the same verb.
Pull is idempotent per blob; apply is idempotent per (path, hash);
commit is idempotent per manifest timestamp. Apply's step 3 gate IS the
post-apply verification — a second full-tree re-hash is redundant and
forbidden.

Cost: ~10 ms per 10 MB on the verify path. Negligible against decompress
wall time.

## The Four Verbs

The core API. Each is direction-preserving, ACID in isolation, and
independently composable.

### Isolation rule

Verbs take only the ports injected at construction and use them.
**Verbs do not construct new interfaces, ports, buses, or adapters.**
No `NewBus`, no `NewPlanner`, no sub-ports. All collaborators arrive via
the constructor. Planning helpers (if any) are **private functions in the
`refs` package**, not new ports.

Storage is the primary collaborator: a `StorageRepository` (local) and a
`StorageRepository` (remote) where the verb needs both; one of them for
verbs that touch only one side. **No separate `RefStore` port.** Ref ops
(list all, get one, put one, delete one) map 1:1 onto `StorageRepository`
V2 (`List`, `GetStream`, `PutStream`, `Delete`); a dedicated port would
only rename methods and duplicate observability already emitted by the
storage decorator on `refs/*.json` keys. Ref encoding / key construction
live as free helpers in `internal/core/domain/ref.go`, written when the
first caller needs them.

Observability is added by wrapping those same ports with decorators at
the composition root. The verb never knows.

```go
type Puller interface {
    Pull(ctx context.Context, id RefID) error
}

type Applier interface {
    Apply(ctx context.Context, id RefID) error
}

type CommitOpts struct {
    Parent  RefID    // default: current HEAD
    Targets []string // default: Parent.Targets
    Amend   RefID    // nil = fresh commit; set = replace unpushed draft
}

type Committer interface {
    Commit(ctx context.Context, opts CommitOpts) (RefID, error)
}

type Pusher interface {
    Push(ctx context.Context, id RefID) error
}
```

### Directional table

| Verb     | Touches instance? | Touches remote?  | Commit point                               |
|----------|-------------------|------------------|--------------------------------------------|
| pull     | no                | read             | manifest + all referenced blobs in local cache |
| apply    | write             | no               | all (path, hash) in manifest materialised in instance/ |
| commit   | read              | no               | new local manifest + all referenced blobs in local cache |
| push     | no                | read + write     | manifest PUT 200 OK **AND** post-PUT fence passes (see Push — ACID) |

### Flush (autosave is disabled for the session)

`save-off` fires exactly once, at readiness, inside the running-stage
strategy — autosave stays off for the server's entire lifetime. Ritual
owns the flush cadence; there is no `save-on` counterpart.

```go
type Flusher interface {
    Flush(ctx context.Context) error   // "save-all flush"
}
```

- Post-stop commit: no flush (server is dead; workdir is stable).
- Live-ticker commit: `Flush` before the walk so pending region writes
  land on disk. No `defer Exit`, no marker file, no startup recovery —
  autosave never comes back on, so there is nothing to re-enable.

Minecraft's autosave interval (~5 min) is the same order as ritual's
ticker cadence, so leaving autosave off costs no durability window
ritual does not already own.

### Composition examples

```go
// Normal session — shape the state graph executes (each line is owned by a state)
lock := acquireLock()
defer releaseLock(lock)
_ = puller.Pull(ctx, remoteHEAD)
_ = applier.Apply(ctx, remoteHEAD)
runServer(ctx)
draft, _ := committer.Commit(ctx, CommitOpts{})
_ = pusher.Push(ctx, draft)
_ = retention.Run(ctx)
_ = gc.Run(ctx)

// Live-ticker (within RunningState, under same lock)
var draft RefID
for range ticker.C {
    _ = flusher.Flush(ctx)          // save-all flush (autosave already off)
    d, _ := committer.Commit(ctx, CommitOpts{
        Parent: sessionHEAD,
        Amend:  draft,                // empty first tick
    })
    draft = d
    if shouldPushThisTick() {
        _ = pusher.Push(ctx, draft)
        _ = retention.Run(ctx)
        _ = gc.Run(ctx)
        sessionHEAD = draft
        draft = RefID{}
    }
}

// Restore to past snapshot
lock := acquireLock()
defer releaseLock(lock)
_ = puller.Pull(ctx, chosenTimestamp)
_ = applier.Apply(ctx, chosenTimestamp)

// Target edit (patch, no data change)
m := cloneHEAD()
m.Targets = append(m.Targets, "forge/**")
validate(m)                            // no orphan paths check
writeLocalManifest(m)
_ = pusher.Push(ctx, m.ID)
_ = retention.Run(ctx)
_ = gc.Run(ctx)
```

## Pull — ACID

### Steps

```
0. Session lock already held by orchestrator.
1. Fetch manifest from remote (in-memory only):
     key = refs/{target_timestamp}.json
     stream GET → ReadAll → json.Unmarshal + validate invariants
     on parse/validate fail: return error; nothing written locally yet
2. For each hash in manifest.objects.values (parallel, 10 workers):
     if exists(objects/{hash}): continue
     stream remote objects/{hash} → compressing-decorator → objects/{hash} direct
     integrity verified on decompression (hash-pipe while writing)
3. Barrier: ∀ hash ∈ manifest.objects.values : exists(objects/{hash})
4. Commit: write refs/{target_timestamp}.json from the in-memory bytes.
   Ref-last commit point: retention and apply can never observe a
   half-pulled ref pointing at missing blobs (mirrors §Commit step 6).
```

### Atomicity

- Per-blob direct write; content-addressed self-verifying names. Partial
  writes detected at read, re-fetched.
- Manifest held in memory until step 4. No on-disk ref exists until every
  referenced blob is present, so a crash mid-pull leaves no live ref for
  retention/apply to act on.
- Transaction-level: idempotent stage replay. Each restart resumes from
  whatever state exists.

### Consistency

Post-condition: `∀ hash ∈ M.objects.values : exists(local objects/{hash})`.
Hash integrity per [Integrity Model](#integrity-model).

### Isolation

Session lock (remote). `.ritual/` owned by ritual for the session.

### Durability

- Local writes: direct + `FlushFileBuffers`. Blobs verified by content-
  addressed name; manifest verified by JSON parse + schema validate on
  next read.
- Remote reads: R2 data already durable.

### Crash recovery

| Crash point | State | Recovery |
|---|---|---|
| Mid manifest fetch | nothing on disk (manifest held in memory) | re-run pull; GET remote ref again |
| Mid blob fetch | partial blob at `objects/{hash}`, no local ref | next read catches mismatch, refetch; no live ref on disk |
| All blobs fetched, before ref commit | blobs present, no `refs/{ts}.json` locally | re-run pull (idempotent); step 2 Exists-gate skips blobs, step 4 writes ref |
| After ref commit | all local state present | pull complete |

## Apply — ACID

### Steps

```
0. Session lock already held by orchestrator.
   Precondition: pull completed for target manifest; all referenced blobs
   present in local objects/.
1. Stale tmp sweep: walk worlds/ + server/ + instance/ ; delete
   *.ritual*.tmp files (see Tmp file naming convention).
2. Pre-create directory tree: MkdirAll every unique dirname(instance/<path>).
3. For each (path, hash) in M.objects (parallel, 10 workers):
     if exists(instance/<path>) AND xxhash(instance/<path>) == hash:
         skip
     tmp = instance/<path>.ritualapply.tmp
     open objects/{hash} → compressing-decorator → zstd.Decoder → write to tmp
     streaming xxhash verify during write
     FlushFileBuffers(tmp)
     os.Rename(tmp, instance/<path>)   (with Windows rename guards, below)
4. Prune: walk instance/ for paths matching M.targets ; delete any path NOT
   in M.objects. Remove empty directories left behind.
```

### Atomicity

Per-file `.ritualapply.tmp`+rename. Observer sees old file or new file,
never torn bytes.
Rename is atomic on same-volume NTFS (which the volume pre-flight ensures).

### Consistency

Hash integrity per [Integrity Model](#integrity-model). Additional scope
invariants:

```
∀ path ∈ walk(instance/) matching M.targets     : path ∈ M.objects
∀ path ∈ walk(instance/) NOT matching M.targets : untouched
```

The second invariant is the scope guard — apply never exceeds its declared
jurisdiction.

### Isolation

Orchestrator precondition: Minecraft not running during apply. Session lock
held. No concurrent ritual session. User in Explorer may see transient state
but takes no consequential action.

### Durability

`FlushFileBuffers` on `.ritualapply.tmp` before rename. NTFS metadata
journal persists rename. No separate directory-fsync required on Windows.

### Crash recovery

| Crash point | State | Recovery |
|---|---|---|
| Stale .ritualapply.tmp from prior session | orphan tmp files | sweep at step 1 |
| Mid per-file write | target unchanged, tmp partial | sweep + re-apply |
| Mid prune | some stale files deleted, some remain | re-run prune |

Each crash + restart is monotone forward progress.

## Commit — ACID

Commit snapshots `instance/` into the local blob cache + a new local
manifest. It does NOT touch remote.

### Fresh commit

```
0. Session lock held; tick-mutex acquired (local).
1. (live-ticker only) Flusher.Flush() → "save-all flush"
   (autosave is already off from boot-time save-off; post-stop path skips this).
2. Build manifest M in memory:
     M.timestamp = now (millisecond)
     M.parent    = opts.Parent (default HEAD)
     M.targets   = opts.Targets (default parent.targets)
3. Walk instance/ with target glob matching:
     for each matched file:
         open shared-read
         stream: file bytes → xxhash pipe → CompressingStorage.Put(objects/{computed_hash})
         record (path, hash) in M.objects
4. Barrier: ∀ hash ∈ M.objects.values : exists(.ritual/objects/{hash})
5. Validate M invariants.
6. Write M: .ritual/refs/{M.timestamp}.json direct → fsync
7. Release tick-mutex. Return M.ID.
```

### Amend

```
0. Same as fresh, plus:
   opts.Amend = D_old (existing local draft ID)
1. Load D_old from .ritual/refs/{D_old}.json
2. Verify D_old NOT on remote:
     HeadObject(refs/{D_old}.json) → 404 expected
     If present: REJECT (amend of pushed manifest forbidden)
3. Steps 1-5 of fresh commit, with:
     M.parent = D_old.parent   (inherit, NOT D_old itself — no chain lengthening)
     M.targets = D_old.targets (or opts.Targets override)
4. Write M (step 6 of fresh).
5. Delete old draft: remove(.ritual/refs/{D_old}.json)
6. Run localGC (see Retention + GC below).
7. Release tick-mutex. Return M.ID.
```

### Atomicity

- Per-blob writes content-addressed direct.
- Manifest direct write. Partial write detected by parse-fail on next
  read; resolved by delete + re-commit.
- Old-draft delete is a single syscall (atomic).
- Ordering: write new manifest BEFORE delete old. Crash between = both
  exist; `max(timestamp)` picks new; stale old cleaned by next recovery
  pass.
- Pre-walk `save-all flush` drains pending region writes so the walk
  sees a stable byte-snapshot in the live-ticker case.

### Consistency

Post-conditions:
```
∀ hash ∈ M.objects.values : exists(.ritual/objects/{hash})
∀ path ∈ M.objects : matches-any-glob(M.targets)
M.parent (if not amend) = prior HEAD's timestamp
```

For amend:
```
M_new.parent == M_old.parent   (no chain growth)
```

### Isolation

- Local tick-mutex prevents concurrent commits.
- Session lock (remote) prevents cross-session interference.
- Pre-walk `save-all flush` prevents Minecraft ↔ ritual read race
  during live-ticker (pending region writes drain before the walk).

### Durability

fsync all local writes (blobs + manifest via Windows `FlushFileBuffers`).

### Live-ticker flush

Autosave is already off from boot — the running-stage strategy writes
`save-off` once at readiness and never re-enables it. The per-tick
sequence is therefore just:

```
save-all flush
    (ritual walks + hashes + compresses + stores blobs — 5–10 s typical)
```

`save-all flush` forces pending region writes to disk and waits for
completion before the walk begins. No `save-on`: ritual owns durability
cadence for the server's lifetime, so re-enabling the built-in autosave
timer would only duplicate work already guaranteed by the next tick's
flush.

Walk+hash+compress duration must fit within a gameplay-acceptable
window. At 10-worker parallelism:
- xxhash ≈ 10 GB/s/core → ~1 s for 1 GB world.
- zstd-3 ≈ 400 MB/s/core → ~2.5 s.
- Total wall ~5–10 s for 1 GB.

Longer worlds → mtime-based incremental walk (same shape as v2
`MtimeScanner` with the size-equality guard):

```go
if info.ModTime().After(since) OR info.Size() != prev.Size:
    re-hash
else:
    carry forward prev.Hash
```

Size check closes the "mtime preserved but content mutated" edge case.

### Crash recovery

| Crash point | State | Recovery |
|---|---|---|
| Mid walk | partial blobs in cache, no manifest yet | local GC reaps partial blobs; next commit starts over |
| Step 4 barrier fail | manifest references missing blob | error surface; abort commit |
| Between manifest write and old-draft delete | both drafts exist briefly | `max(timestamp)` wins; superseded-draft sweep on next session |
| After manifest commit | clean state | done |

## Push — ACID

Push uploads a local manifest + its referenced blobs to remote.

### Steps

```
0. Session lock held; client remembers my.sessionId.
1. Load local manifest M from .ritual/refs/{id}.json.
2. For each hash in M.objects.values (parallel, 10 workers):
     if storage.Exists(ctx, "objects/"+hash): continue
     open .ritual/objects/{hash}          (io.ReadSeeker for known size)
     storage.Put(ctx, "objects/"+hash, body)
3. Barrier: ∀ hash ∈ M.objects.values : Exists(remote objects/{hash})
4. Pre-PUT fence verify:
     GET /lock → parse payload
     require payload.sessionId == my.sessionId
     on mismatch: abort push, return ErrLeaseLost (no manifest PUT fired)
5. Manifest PUT:
     storage.Put(ctx, "refs/"+M.timestamp+".json", manifestBody)
     with If-None-Match: *   (first push ever)
     OR no conditional header (subsequent pushes — new timestamp never collides)
6. Post-PUT fence verify (mandatory, not optional):
     GET /lock → parse payload
     if payload.sessionId != my.sessionId:
         best-effort DELETE refs/{M.timestamp}.json    (zombie rollback)
         return ErrLeaseLostAfterPut  (loud error — orphan cleanup may still be visible briefly)
     else:
         storage.Exists(ctx, "refs/"+M.timestamp+".json") == true   (durability check)
```

### Atomicity

- Per-blob conditional PUT, content-addressed, idempotent.
- Manifest PUT is the single atomic commit point remotely.
- Fencing (steps 4 + 6) closes the zombie-writer silent-loss window: a
  session that lost its lease between step 4 and step 6 performs
  best-effort self-rollback and surfaces a loud error, rather than
  letting its stale write stand unnoticed.
- One linearization moment per successful push: manifest PUT returns 200
  AND post-PUT fence passes. If post-PUT fence fails, this session's
  commit point is retracted (self-DELETE) and the legitimate takeover
  session's future push provides the next linearization.

### Consistency

Internal barrier (step 3) before manifest PUT: every referenced blob is
durable on remote.

Post-condition (on successful push):
```
∀ hash ∈ M.objects.values : exists(remote objects/{hash})
exists(remote refs/{M.timestamp}.json)
payload(lock).sessionId == my.sessionId   (at step 6)
```

On fenced abort (step 4 mismatch): no manifest written. Blobs remain
on remote (content-addressed; will be either GC-collected or re-used by
the takeover session's own push — both are safe outcomes).

On fenced rollback (step 6 mismatch): manifest self-DELETE attempted.
Blobs remain as above. The zombie session returns a loud error.

### Isolation

Remote session lock held throughout. No other writer. `HEAD = max(timestamp)
in refs/` is unambiguous because only this session is appending.

### Durability

R2 SLA on 200 responses.

### R2 atomicity caveat

Cloudflare R2 docs (retrieved 2026-04-20) guarantee:
- Strong read-after-write consistency.
- CopyObject immediately readable on completion.
- Conditional PUT via `If-Match`, `If-None-Match`, `If-Modified-Since`,
  `If-Unmodified-Since` headers with 412 PreconditionFailed on mismatch.

R2 docs do NOT warrant:
- PutObject partial-write / torn-byte behaviour on failure.
- CopyObject destination state on failure.
- CAS linearizability of conditional PUT.

**Mitigation**: the four-verb design keeps push to a single PUT per manifest
(no Copy-before-PUT dance). Derived HEAD (no HEAD.json) means no
multi-object transaction atomicity is ever required. `If-None-Match: *` on
init PUT prevents accidental overwrite. Post-PUT Exists-verify closes the
client-timeout ambiguity.

### Crash recovery

| Crash point | State | Recovery |
|---|---|---|
| Mid blob upload | some blobs durable, manifest not PUT | next push skips uploaded blobs via Exists check |
| All blobs uploaded, before manifest PUT | all blobs present, manifest missing | retry manifest PUT |
| Client timeout on manifest PUT, server committed | HEAD = new | next session sees new HEAD; no double-commit (idempotent retry = same bytes) |
| Client timeout, server rejected | HEAD = old | retry |
| Lease lost between step 4 and step 5 (pre-PUT fence caught it) | no manifest written, blobs uploaded | abort with ErrLeaseLost; blobs harmless (GC or re-used) |
| Lease lost between step 5 and step 6 (post-PUT fence caught it) | manifest briefly present, then self-DELETEd | loud ErrLeaseLostAfterPut; zombie session knows its write was rolled back |
| Zombie self-DELETE crashes before completing | manifest file orphaned remotely | takeover session's pull ignores orphan via max(timestamp); retention GCs it next cycle |

No HEAD.json pointer means no "stranded push" state. Any manifest file
present IS a real manifest at its own timestamp (modulo the brief
zombie-rollback window above).

### Triggers (structural, no conditionals)

```
push       → retention → gc
amend      → localGC
```

Push is purely additive (adds blobs + manifest) and does NOT trigger GC
directly. Retention may drop manifests (the only operation that orphans
blobs), and GC follows as a no-branch loop.

### Retention policy

```go
type Policy struct {
    Last    int    // keep N most recent regardless
    Daily   int    // one per calendar day, N days
    Weekly  int    // one per ISO week, N weeks
    Monthly int    // one per calendar month, N months
}

func (p Policy) Select(refs []ManifestRef, now time.Time) (keep, drop []ManifestRef)
```

Pure function, table-driven tested.

Defaults from binary (overridable via `settings.json`):
- **Local**: `Last: 2`. Shallow — local cache is ephemeral; remote is
  authoritative.
- **Remote**: `Last: 2, Daily: 7, Weekly: 4, Monthly: 6`.

### Retention algorithm

```go
func (r *Retention) Run(ctx) (dropped []string, err error) {
    keys, err := r.storage.List(ctx, "refs/")
    if err != nil { return nil, err }
    refs := parseTimestamps(keys)                           // client-side
    _, drop := r.policy.Select(refs, time.Now())
    for _, d := range drop {
        _ = r.storage.Delete(ctx, d.Key)                    // fail-continue
        dropped = append(dropped, d.Key)
    }
    return
}
```

Built on the `StorageRepository` port. Same implementation used for local
(via `FSRepository`) and remote (via `R2Repository`). The only difference
between local and remote retention is the injected storage.

### GC algorithm

```go
func (g *GC) Run(ctx) (freed []string, err error) {
    live := make(map[string]struct{})
    mKeys, _ := g.storage.List(ctx, "refs/")
    for _, k := range mKeys {
        body, err := g.storage.Get(ctx, k)
        if err != nil { continue }                          // fail-continue
        defer body.Close()
        m, _ := decodeManifest(body)
        for _, h := range m.Objects { live[h] = struct{}{} }
    }
    bKeys, _ := g.storage.List(ctx, "objects/")
    for _, b := range bKeys {
        hash := path.Base(b)
        if _, ok := live[hash]; ok { continue }
        _ = g.storage.Delete(ctx, b)                        // fail-continue
    }
    return
}
```

Same implementation for local and remote (different injected storage).

### No grace period

Under the single-writer session-lock invariant, no concurrent push can
interleave with GC. Mark-sweep from live manifests is the sole protection.
Dropping the grace period eliminates a tunable + removes the need for
per-blob `LastModified` metadata.

If daemon GC is ever added, grace period returns as belt-and-suspenders. Not
planned.

### Local GC after amend

Amend creates local orphan blobs (superseded draft's unique hashes). Local
GC runs immediately after amend:

```go
committer.Commit(ctx, CommitOpts{Amend: D_old}) → D_new
localGC.Run(ctx)     // mark-sweep against all local manifests
```

Keeps `.ritual/objects/` bounded across ticker cycles.

### Push → retention → GC chain

```go
push(draft)
retention.Run(ctx)
gc.Run(ctx)
```

Each is a pure function of current state. No "did retention drop anything?"
check — the GC loop iterates zero times if nothing is orphan. Structural
composition; no flag-gated conditional.

### Amend-push collapse is emergent

With `keep last 1` retention:

```
commit(nil) → D1; push(D1) → remote [T1]; retention keeps [T1]
amend(D1)   → D2 (local); push(D2) → remote [T1, T2]; retention drops T1
amend(D2)   → D3 (local); push(D3) → remote [T2, T3]; retention drops T2
```

Remote ends at `[T3]`. Intermediate tick blobs never leave local disk (D2's
blobs orphaned locally by amend → localGC reaps). Push is oblivious to
whether amend happened.

### HEAD-duplicate concern (does not apply)

Earlier designs with a separate `HEAD.json` pointer had a retention bug: a
duplicate archive (HEAD.json and `{old.ts}.json` momentarily identical
during push) could be counted as a retention slot and prematurely drop the
real prior backup.

**This bug cannot occur in the current design.** HEAD is derived from
max(timestamp), not a separate file. There is no second copy of HEAD to
confuse retention with.

## Storage Repository Interface

### Shape

```go
type ObjectInfo struct {
    Key  string
    Size int64   // bytes on storage (compressed for objects/, raw for refs/)
}

type StorageRepository interface {
    GetStream(ctx context.Context, key string) (io.ReadCloser, int64, error)
    PutStream(ctx context.Context, key string, body io.ReadSeeker) error
    Exists(ctx context.Context, key string) (bool, error)
    Delete(ctx context.Context, key string) error
    DeleteBatch(ctx context.Context, keys []string) error
    List(ctx context.Context, prefix string) ([]ObjectInfo, error)
    Copy(ctx context.Context, src, dst string) error
}
```

### Per-method rationale

- **GetStream → `(io.ReadCloser, int64, error)`**: size from
  HTTP `Content-Length` (R2) or `os.Stat` (FS). Caller uses size for
  wire-level plan totals (ETA, Mb/s label). Streaming decompress +
  integrity verify without buffering. Caller `defer Close()`.
- **PutStream → `io.ReadSeeker`**: R2/S3 PutObject requires
  `Content-Length`; SDK discovers size via `Seek(0, io.SeekEnd)`. `*os.File`
  and `bytes.NewReader` both satisfy. Ritual always has a seekable source
  (the content-addressed blob already on disk).
- **Exists**: `HeadObject` remotely, `os.Stat` locally. Cheap pre-check for
  push (skip already-uploaded blobs) and apply (skip already-correct files).
- **Delete** / **DeleteBatch**: port accepts **unlimited** keys in one
  `DeleteBatch` call. Adapter internally chunks into 1000-key S3 calls
  (`DeleteObjects` max); callers never see the paging limit. Local FS
  loops `os.Remove`.
- **List → `[]ObjectInfo`**: port returns **all** entries for a prefix in
  one call. Adapter walks continuation tokens internally until exhausted.
  Callers never page. Same call feeds retention, GC, HEAD derivation, and
  compressed-size totals for pull-plan (`WireTotal = Σ info.Size` across
  planned downloads).
- **Copy**: kept in the port for symmetry and possible future flows; not
  load-bearing in the current design (no Copy-before-PUT dance).

### Paging / batching is an adapter concern

The port contract hides S3 pagination and delete-batch limits. Higher
layers (verbs, retention, GC) see one call that returns everything or
deletes everything. Domain code stays free of vendor-specific transport
quirks; tests against the port uniform across adapters (FS, R2) — all
return exhaustive results. FS is the only backend needed for tests and
dev; R2 attaches only in staging/prod.

### Etag / conditional writes

Not used in Phase 1. The `Locker` (see §Lock Discipline) composes over
the general `StorageRepository` port and relies on `sessionId`-based
read-verify-mutate for fencing instead of conditional-PUT CAS. Port
surface exposes no etag type and no adapter parameter shape for
conditional options. Rationale: the operational single-writer invariant
(low user count, coordinated session start, single-binary version)
makes same-instant races cosmically unlikely; `sessionId` read-back at
verb fences surfaces any silent clobber as `ErrLeaseLost` within one
heartbeat cycle. If multi-host incidents are ever observed, Phase 2 may
reintroduce etag support on a dedicated adapter; Phase 1 keeps the port
clean.

### Streaming-without-disk is out of scope

Non-goal: blobs always materialise to `.ritual/objects/{hash}` before
upload. Compressor output → disk → seekable-reader → upload. Never
compressor → uploader directly. `io.ReadSeeker` fits this model.

### Compression decorator

```go
type compressingStorage struct {
    inner StorageRepository
    level int
}

func (c *compressingStorage) Put(ctx, key string, body io.ReadSeeker) error {
    // compress to temp file (seekable), then Put
    tmp, _ := os.CreateTemp("", "zstd-*")
    defer os.Remove(tmp.Name())
    enc, _ := zstd.NewWriter(tmp)
    _, _  = io.Copy(enc, body)
    _     = enc.Close()
    _, _  = tmp.Seek(0, io.SeekStart)
    return c.inner.Put(ctx, key, tmp)
}

func (c *compressingStorage) Get(ctx, key string) (io.ReadCloser, error) {
    raw, err := c.inner.Get(ctx, key)
    if err != nil { return nil, err }
    return &verifyingReader{
        inner:        zstd.NewReader(raw),
        expectedHash: key,
    }, nil
}
```

Decorator applied ONLY to the `StorageRepository` instance that operates on
`objects/`. Manifests bypass the decorator (plain JSON, pass-through).

### Encoder + buffer pools

POC-proven memory wins:

- One `zstd.Encoder` per worker, reused via `Reset(sink)` per blob. Measured
  heap 259 MB → 198 MB, GC cycles 153 → 3.
- `sync.Pool[*[]byte]` with 64 KB buffers for `io.CopyBuffer`. Pointer-to-
  slice (not slice-value) avoids interface boxing per Put. Pattern per
  `SA6002`.

```go
var copyBufPool = sync.Pool{
    New: func() any {
        b := make([]byte, 64*1024)
        return &b
    },
}
```

### Worker count — 10

POC measured 10 workers saturates every tested link (20 Mbps → 1 Gbps). Pipe
bandwidth is always the cap; CPU never is. Higher counts don't help.
Hardcoded `N = 10`, not operator-tunable (one number, every deployment).

### Remote lock object

Lives at `{prefix}/lock` — root, NOT under `refs/`. Keeping it outside
the manifest prefix means retention/GC can walk `refs/*` without
filtering out the lock.

**Existence semantics**: object exists only while a session holds the lock.
Absence = unlocked. Release = `Delete`. There is no "permanent lock file
with a free/held flag" — presence IS the held signal.

### Payload

Five fields. All load-bearing.

```json
{
  "owner":       "hostnameA",
  "sessionId":   "b1e6f1c2-8a9d-4a2e-9f1b-2e0c8f3a1d77",
  "acquiredAt":  "2026-04-21T10:17:44Z",
  "heartbeatAt": "2026-04-21T10:18:14Z",
  "expiresAt":   "2026-04-21T10:20:44Z"
}
```

| Field | Purpose |
|---|---|
| `owner` | Hostname of the holder. Human-readable identity for "who is blocking me" messages. Sufficient for diagnostics; NOT used for identity fencing. |
| `sessionId` | UUIDv4 generated at acquisition. Opaque fencing token. Client remembers its own; every session-critical write re-verifies `lock.sessionId == my.sessionId`. Changes on every (re-)acquisition, so post-expiry takeover yields a distinct identity even if owner hostname repeats. |
| `acquiredAt` | When this session took the lock. Never updated during the session's lifetime. Diagnostic — surfaces "locked for N min" in UI. |
| `heartbeatAt` | When the holder last renewed. Changes with every heartbeat. Proof of liveness. |
| `expiresAt` | Wall-clock deadline past which the lock is considered stale. Computed at write time as `heartbeatAt + (heartbeatInterval × 5)`. Stored in the payload, NOT derived by readers. |

**Why `expiresAt` lives on the wire and not in client config**:

- Data-driven. Readers compare `now > payload.expiresAt`. Zero reliance on
  client-side lease constants.
- Version-skew safe. If lease heuristics evolve across binary versions,
  the lock is self-describing at the moment of acquisition.
- Test-override friendly. Tests can write short-lease locks without
  binary reconfiguration.
- Heartbeat cadence can vary with workload — expiry tracks the actual
  cadence, not a static assumption.

`owner` needs no PID, no nonce. Hostname + single-lock-per-host invariant
uniquely identifies the machine holding it. Operator diagnoses further
with local `tasklist | findstr ritual` on the named host.

### Fields explicitly NOT in the payload

| Dropped field | Why |
|---|---|
| `lockID` with nanosecond suffix | `sessionId` UUIDv4 occupies the nonce slot with stronger uniqueness guarantees |
| `ritualVersion` | `RitualUpdater` enforces a single binary version; no cross-version lock conflict possible |
| `pid` | Hostname + `sessionId` uniquely identifies the holder on the wire; local PID diagnosis is out of scope for the wire format |
| `epoch` (monotonic counter) | R2 has no native monotonic-counter primitive. Simulating via `If-Match` CAS on lock acquire suffices for concurrent-takeover races (captured below). Full epoch-in-manifest-key fencing is deferred to a future phase if real incidents warrant it. |

### Acquire / takeover (unified path)

Client generates a fresh `sessionId = uuidv4()` locally and remembers it
for the lifetime of the session. The operational invariant (low user
count, coordinated session start, single-binary version) constrains
concurrent writers to near-zero; the protocol replaces conditional-PUT
CAS with `sessionId`-based read-verify-mutate so the Locker composes
over the general `StorageRepository` port with no etag plumbing.

```
sessionId = uuidv4()

GET /lock
  not found                        → unlocked. Fresh-acquire branch.
  found + body                     → parse payload. Takeover branch.

Fresh-acquire branch:
  PUT /lock with the new payload   → lock held; sessionId persisted.

Takeover branch:
  if now < payload.expiresAt:
      abort "locked by {owner} (session {sessionId[:8]}) until {expiresAt}"
  else:
      PUT /lock with the new payload → takeover succeeded; our sessionId
      replaces the expired one.
```

**Why no conditional PUT.** Under the single-writer operational
invariant, two sessions racing the same fresh-slot or expired-lease PUT
is cosmically unlikely; if it did happen, the sub-RTT window would leave
one session's identity silently clobbered. Fence checks at verb
boundaries (`Verify`) and heartbeat (`Heartbeat`) both re-read the
payload and compare `sessionId`; a silent clobber surfaces as
`ErrLeaseLost` within one heartbeat cycle. Zombie-writer scenarios are
handled by pre- and post-commit fencing in `Push` (see §Push ACID), not
by etag.

### Heartbeat

The holder keeps the lock alive by rewriting the payload with fresh
`heartbeatAt` + `expiresAt`. `owner`, `sessionId`, and `acquiredAt` stay
pinned.

```json
{
  "owner":       "<unchanged>",
  "sessionId":   "<unchanged>",
  "acquiredAt":  "<unchanged>",
  "heartbeatAt": "<now>",
  "expiresAt":   "<now + heartbeatInterval × 5.2>"
}
```

Every heartbeat is a GET-verify-PUT: read the remote payload, confirm
its `sessionId` still matches the holder's token, write the refreshed
payload. Mismatch or absence raises `ErrLeaseLost`: abort the session,
do NOT retry, surface the loss to the orchestrator so any in-flight
verb can unwind before silent corruption.

**No background goroutine.** Process crash kills any goroutine, and the
failure mode we want on crash is exactly "no more heartbeats, lease
expires, next session takes over". Heartbeating is driven inline by the
main flow — any thread blocked inside a verb IS the thread that needs to
stay heartbeating.

Heartbeat cadence:
- **At every verb boundary** (end of pull, apply, commit, push) — each
  verb's finalisation PUTs the lock with a fresh heartbeatAt.
- **Inside long-running loops** (worker pool in pull/push) — a
  coordinating loop checks `time.Since(lastHeartbeat) > heartbeatInterval`
  between blobs and fires one PUT cooperatively. Per-worker heartbeating
  would serialize on the lock object; one coordinator suffices at 1 min
  cadence.

### Lease tuning

- `heartbeatInterval = 1 min` (`lock.DefaultHeartbeatInterval`, public
  field on the `Locker` struct — how often we ping).
- `expiresAt = heartbeatAt + heartbeatInterval × 5.2` → 312 s (5 min
  12 s) from last heartbeat. Multiplier of 5.2 tolerates transient
  network flakes, GC pauses, or OS scheduler delays without premature
  takeover; the `.2` margin past the fifth heartbeat absorbs a full RTT
  plus GC jitter without risking false-positive expiration at exactly
  `5 × interval`. Multiplier lives on the struct as
  `lock.DefaultTTLMultiplier`.
- Crash → up to 5 min 12 s dead window before takeover. The tighter
  window shrinks the realistic zombie-writer race from "weekly on
  laptops with sleep/wake" to "narrow Kleppmann-class pause" — and the
  post-PUT fencing (see Push ACID) converts what residual remains into a
  loud abort, not silent loss.

**Cost:** at 1 min cadence a session heartbeats ~1440 PUTs/day. R2
Class A write pricing ≈ $4.50 / million → ~$0.006/day per always-on
session. Solo users at ~4 h/day active usage: ~$0.40/year. Negligible.

**Why the decoupling matters.** Heartbeat runs on its own cadence; push
does not gate it. The live-ticker TBD section (above) makes this
explicit: heartbeat keeps the lease alive through slow pushes,
operator-paused commits, and any commit-side failure that isn't also a
network failure. Without decoupling, a slow push would force a generous
TTL to avoid spurious takeover; with decoupling, TTL can track the
actual crash-detection budget, not the worst-case verb duration.

`heartbeatInterval` lives in binary config; `expiresAt` lives on the wire
(derived from heartbeatInterval at write time but persisted explicitly so
readers need no config).

### Release

```
GET /lock
  not found      → lock already gone (crashed + swept by takeover); done.
  found + body   → parse payload.
                    if payload.sessionId != my.sessionId:
                        return nil  (the lock is no longer ours — silent no-op)
                    else:
                        DELETE /lock
                          ok  → released cleanly.
```

At session end, after last verb + retention + gc. The sessionId check
before DELETE prevents the "we crashed, came back, someone else took
over, and we delete their lock on cleanup" footgun. The residual TOCTOU
between GET and DELETE is operationally negligible (single-writer
invariant).

### Race on simultaneous takeover

Two sessions both read the same expired lock at the same instant and
both attempt to take over.

**Operationally closed.** Under the single-writer invariant (low user
count, coordinated session start, single-binary version via
`RitualUpdater`), two sessions arriving at the same expired lease
simultaneously does not happen in practice. If it did, the post-PUT
`Verify` check on the second session's first fence point would surface
the clobber as `ErrLeaseLost` within one heartbeat cycle. The prior
conditional-PUT mitigation is retracted — the etag plumbing it required
is excessive against this risk class.

### Zombie writer (post-takeover)

Separate class from the above. A previously-valid holder stalls past the
TTL (OS sleep, antivirus pause, GC stall, network blackhole with
sockets preserved). Another session legitimately takes over. The
original process then resumes and attempts a write — still believing its
lease is live.

**Pre-push re-verify** (before the manifest PUT): GET /lock, check
`sessionId == my.sessionId`. If mismatch → abort before linearization.
Closes the bulk of the window.

**Post-push fencing** (after the manifest PUT lands): re-GET /lock,
check `sessionId == my.sessionId`. If mismatch → the zombie manifest has
landed; best-effort `DELETE refs/{M.timestamp}.json` to clean up,
then return a loud error. See Push ACID for the exact step ordering.

**Residual TOCTOU windows after both checks:**

1. Between pre-verify and manifest PUT (~network RTT): takeover could
   happen in this gap. Post-PUT check catches it.
2. Between manifest PUT and post-verify (~network RTT): takeover could
   happen here. Post-verify still detects, surfaces loud error to the
   zombie session.
3. Between zombie's manifest PUT and zombie's self-DELETE: a concurrent
   puller on another session could observe the zombie manifest as HEAD,
   apply it, and push a new manifest referencing it as parent. The
   zombie's self-DELETE then breaks that chain. **Not closed in Phase 1.**

Phase 1 guarantee: **no silent data loss**. The zombie session is
informed via loud error. The pull-contamination case (3) is documented
as a rare residual; Phase 2 (lock session/epoch carried in manifest body,
read-side zombie filter) is the path if real incidents warrant it.

Operators still should not start two rituals against the same world
deliberately — the lock remains coordination first, fencing second.

### Canonical errors

Every fence failure surfaces as one of a small sentinel set. Callers
match with `errors.Is` and map to orchestrator handling uniformly —
retries, user-visible messages, and termination policy are decided
per-sentinel, not per-call-site. The sentinels live in
`internal/core/lock` and are re-exported from verbs that raise them.

```go
package lock

import "errors"

// ErrLocked is returned when acquisition finds a live lease owned by
// someone else. Not a failure of this session — it never held a lease.
// Raised by: Locker.Acquire (takeover branch, non-expired body).
var ErrLocked = errors.New("lock: held by another session")

// ErrAcquireRace is reserved for a same-instant takeover race detected
// after a read-back fence on the newly-written payload. Retryable via
// Acquire again. Unused under the current operational invariant;
// retained as a sentinel so Phase 2 fencing can land without callers
// changing.
var ErrAcquireRace = errors.New("lock: acquisition race, retry")

// ErrLeaseLost is raised when a pre-operation fence check observes
// that this session's sessionId no longer matches the remote lock
// body, or the lease has vanished. The session has been taken over
// mid-flight. No remote linearization happened; no rollback needed.
// Raised by: Locker.Heartbeat; Locker.Verify; Push (pre-PUT fence).
var ErrLeaseLost = errors.New("lock: lease lost before commit point")

// ErrLeaseLostAfterPut is raised when the post-PUT fence check
// observes a sessionId mismatch AFTER the manifest PUT has landed.
// The session performs best-effort self-DELETE of the orphaned
// manifest and surfaces this error loudly — the session's write was
// retracted, not committed.
// Raised by: Push (post-PUT fence).
var ErrLeaseLostAfterPut = errors.New("lock: lease lost after commit point, manifest rolled back")
```

**State-level handling matrix** (owned by the state running the verb —
see §Session Orchestrator doctrinal note: "orchestrator" is the state
machine itself, not a new component):

| Error | Mid-session? | Session outcome | Retention/GC | User-visible |
|---|---|---|---|---|
| `ErrLocked` | n/a (pre-session) | never started | untouched | "locked by {owner} until {expiresAt}" |
| `ErrAcquireRace` | n/a (pre-session) | retry internally | untouched | silent (transient) |
| `ErrLeaseLost` | yes | terminate, no release call | skip (we own nothing remote) | "lease taken over; your session was stalled too long" |
| `ErrLeaseLostAfterPut` | yes | terminate, no release call | skip | "your last push was rolled back; re-sync on next start" |

`errors.Is` discrimination keeps verb code uncoupled from policy: a
verb returns the sentinel; the state that invoked it decides the
transition (retry, terminate, rollback) from the error class.

### Session-scoped, not verb-scoped

```go
func RunSession(ctx) error {
    lock, err := acquireLock(ctx)
    if err != nil { return err }
    defer releaseLock(lock)
    // all verbs + retention + gc run inside this scope, with inline heartbeat
}
```

Verbs themselves are lock-agnostic; the Locking / Running / Unlocking
states own the lock lifecycle and the heartbeat schedule. No separate
lock coordinator exists outside the state machine.

### TBD — decoupled heartbeat ticker in RunningState

> **Out of scope for initial v2.1 implementation.**
>
> Live-ticker commit+push and lock heartbeat will run on independent
> cadences in RunningState (two tickers in one `select`, same goroutine).
> Decoupling lets the lock stay alive during slow pushes, during operator-
> paused commits, and through any commit-side failure mode that isn't also
> a network failure.
>
> Intra-verb heartbeating (inside worker-pool loops) may require
> short-lived per-verb goroutines whose lifetime ≤ verb lifetime ≤ lease

> verb-scoped helpers.
>
> Not designed in detail here. Flagged for follow-up story once the
> single-ticker model ships and measured failure modes inform the split.

## Session Orchestrator

> **Doctrinal note — READ BEFORE IMPLEMENTING.**
>
> "Orchestrator" in this document is a **role**, not a component. The
> existing state machine (`internal/core/statemachine/` and its state
> packages) plays that role. Do NOT build a standalone orchestrator,
> session coordinator, or choreographer on top of the state machine —
> such a component always degrades into a choreographer and duplicates
> the state graph it sits on.
>
> The session flow below is a **state graph**. Each numbered step is a
> state; each verb (pull / apply / commit / push / retention / collect)
> is a dependency injected into the state it belongs to. Transitions are
> state-internal: a state decides its successor from its own Run result.
>
> **Events / the event bus are downstream sinks** — GUI progress, logs,
> metrics. They do NOT drive transitions. Subscribers observe; they do
> not control.
>
> Implementation instruction: **extend** the existing state machine.
> Add states for verbs that lack them, remove states tied to obsolete
> v2 concepts (staging-dir init/cleanup, orphan cleanup paths for
> tar-based sync, etc.). Each state is unit-tested in isolation with
> mocked verbs.

### Normal session flow

```
acquireLock()
preflight()                   ← establish equalities; heal if needed
runServer(...)                ← Minecraft lifecycle (state machine)
commit(CommitOpts{})          ← capture post-stop instance
push(localHEAD)               ← publish
retention.Run()               ← collapse older manifests
gc.Run()                      ← sweep unreferenced blobs
releaseLock()
```

Pull and apply are not unconditional session-start verbs — they are
healing verbs invoked by preflight when an equality check fails. If both
equalities already hold (typical case after a clean prior session),
preflight returns without calling them.

### Preflight

Mandatory gate between `acquireLock()` and any verb. Establishes two
byte-level equalities. **No divergence tolerated** — any violation heals
deterministically, or aborts the session.

Steps:

1. Volume pre-flight (per Windows Platform Guards).
2. Stale-tmp sweep (`*.ritual*.tmp`, per Tmp file naming convention).
3. Local-draft reconciliation — `max(timestamp)` in `.ritual/refs/`
   elects local HEAD. Superseded drafts (any draft whose timestamp is
   less than local HEAD AND not a remote-pushed manifest) deleted.
4. **Equality #1 — local files ≡ local manifest**:

   ```
   ∀ (path, hash) ∈ local_HEAD.objects : xxhash(instance/<path>) == hash
   ∀ path ∈ walk(instance/) matching local_HEAD.targets : path ∈ local_HEAD.objects
   ```

   Heal on violation:
   - Referenced blob present in `.ritual/objects/` → `apply(local_HEAD)`
     rewrites divergent files from local blobs.
   - Referenced blob missing → `pull(local_HEAD)` first, then `apply`.
   - Post-heal re-run of the check. Second violation → FATAL
     (`ErrPreflightUnhealable`, operator intervention).


5. **Equality #2 — local HEAD ≡ remote HEAD**:

   ```
   local_HEAD.timestamp == remote_HEAD.timestamp
   local_HEAD.objects   == remote_HEAD.objects
   local_HEAD.targets   == remote_HEAD.targets
   ```

   Heal per state:

   | State | Action |
   |---|---|
   | timestamps + bytes equal | ok, proceed |
   | local.ts > remote.ts (local has unpushed draft) | `push(local_HEAD)`; re-run check |
   | local.ts < remote.ts (local behind) | `pull(remote_HEAD)` + `apply(remote_HEAD)`; re-run Equality #1 then re-run this check |
   | local.ts == remote.ts, bytes differ | FATAL (`ErrPreflightHistoryDivergence`) — single-writer invariant violated; operator intervention |

6. Preflight returns OK iff both equalities hold byte-for-byte. Any
   unhealable violation surfaces a canonical sentinel and the session
   does not proceed to `runServer`.

Preflight is the integrity gate. Apply's step 3 hash gate is the
mechanism; preflight is the contract.

#### Canonical preflight errors

```go
package preflight

import "errors"

// ErrPreflightUnhealable is raised when Equality #1 (local files ≡
// local manifest) fails after a healing attempt. Local blobs missing or
// post-apply hash mismatch persists. Operator intervention required.
// Raised by: Preflight step 4 (second-attempt check).
var ErrPreflightUnhealable = errors.New("preflight: local state unhealable against local manifest")

// ErrPreflightHistoryDivergence is raised when Equality #2 finds
// local_HEAD.ts == remote_HEAD.ts but bytes differ. Violates the
// single-writer invariant; cannot heal automatically without choosing
// a winner.
// Raised by: Preflight step 6 (same-timestamp branch).
var ErrPreflightHistoryDivergence = errors.New("preflight: same-timestamp manifests with divergent content")

// ErrPreflightRemoteMissing is raised when remote refs/ prefix
// is empty and local HEAD exists. Indicates remote bucket wipe or
// misconfiguration; operator must run `ritual init` or restore remote.
// Raised by: Preflight step 6.
var ErrPreflightRemoteMissing = errors.New("preflight: remote HEAD missing, local HEAD present")
```

Orchestrator handling matrix:

| Error | Session outcome | User-visible |
|---|---|---|
| `ErrPreflightUnhealable` | abort pre-runServer, release lock | "local state cannot be reconciled to manifest {ts}; run `ritual doctor`" |
| `ErrPreflightHistoryDivergence` | abort, release lock | "remote manifest {ts} differs from local same-timestamp manifest; two writers suspected" |
| `ErrPreflightRemoteMissing` | abort, release lock | "remote state missing; run `ritual init` or restore bucket" |

### Init ceremony (first-ever session for a world)

Separate command: `ritual init`. Preconditions:
- Remote `refs/` is empty (no HEAD).
- Lock acquirable.

```
acquireLock()
commit(CommitOpts{Parent: nil, Targets: DefaultTargets})  ← captures existing instance/
push(localHEAD)                                              ← first remote manifest
releaseLock()
```

Failure in any step → rollback (delete any uploaded blobs, release lock, no
manifest commit). Either fully initialised manifest ∧ instance pair, or
nothing.

After init, the manifest ∧ instance invariant holds forever, enforced on
every subsequent session by Preflight.

### Runtime invariant

Every subsequent session asserts, via Preflight:
1. Remote has a HEAD manifest.
2. Local files ≡ local HEAD manifest (byte-level).
3. Local HEAD manifest ≡ remote HEAD manifest (byte-level).

No implicit fallback to binary defaults. If HEAD is missing on remote,
session fails with clear error; operator runs `ritual init` if appropriate.

### Live-ticker (within RunningState)

Implementation note: the loop below is a **self-transition inside the
existing RunningState**. It is not a separate orchestrator, not a
subscriber on a bus, not a background goroutine spawned from some
parent coordinator. RunningState drives its own cadence by calling
the committer / pusher it holds as dependencies, and transitions out
of itself when the runner exits or an unrecoverable error surfaces.

```go
ticker := time.NewTicker(tickInterval)
defer ticker.Stop()
var draft RefID

for {
    select {
    case <-ctx.Done():
        return
    case <-ticker.C:
        if err := flusher.Flush(ctx); err != nil { logError(err); continue }
        opts := CommitOpts{Parent: sessionHEAD}
        if draft != (RefID{}) {
            opts.Amend = draft
        }
        d, err := committer.Commit(ctx, opts)
        if err != nil { logError(err); continue }
        draft = d

        if shouldPushNow() {
            if err := pusher.Push(ctx, draft); err != nil { logError(err); continue }
            _, _ = retention.Run(ctx)
            _    = gc.Run(ctx)
            sessionHEAD = draft
            draft = RefID{}
        }
    }
}
```

`shouldPushNow()` is policy (e.g. every N ticks, or only on session end).
Intermediate ticks accumulate amends locally; only pushed drafts escape to
remote.

### Restore flow

```
acquireLock()
pull(chosenTimestamp)         ← fetch old manifest + its blobs
apply(chosenTimestamp)        ← materialise instance/ to old state
(operator may: runServer, commit, push — establishes new branch by parent=chosen)
releaseLock()
```

### Patch flow (target edit only, no data change)

```
acquireLock()
m := cloneHEAD()
m.Targets = editedTargets
validate(m)                   ← no orphan paths after shrink; all globs parse
writeLocalManifest(m)         ← synthetic commit (no new blobs)
push(m.ID)
retention.Run()
gc.Run()
releaseLock()
```

If new targets exclude paths currently in `m.objects`, validation fails
with "removing `<glob>` would orphan N paths; use `ritual forget` to drop
them first." Forces explicit data-loss decisions.

## Windows Platform Guards

### Tmp file naming convention

Pattern: `{targetName}.ritual{scope}.tmp` where `{scope}` names the verb
owning the write.

| Scope | Verb | Usage | Lives under |
|---|---|---|---|
| `apply` | Apply | per-file materialise before rename | `worlds/`, `server/` |

Every other write path is direct — blobs (content-addressed name IS the
integrity check), manifests (parse-fail on read triggers delete +
refetch/re-commit), lock payload (single PUT, R2-atomic). Only apply
needs tmp today because the target filename is pre-chosen, world-visible,
and must flip atomically from old-bytes to new-bytes.

**Adding a new scope**: any future verb that needs atomic rename allocates
a distinct `ritual{scope}` label (e.g. `ritualrestore`). Never reuse
`apply`. Never share a scope across verbs — scope IS the ownership tag.

**Sweep rule**: session start (after lock) walks tracked roots and deletes
every `*.ritual*.tmp`. The glob matches any allocated scope automatically
— no sweep-code change when a new scope is added. Foreign `.tmp` files
without the `ritual` prefix are never touched.

**Uniqueness**: intra-session collision impossible because each verb
writes one tmp per unique target path and walks its target set without
duplication. Cross-session: prior-session stale tmp is overwritten by
`O_TRUNC` on open, or swept at next session start.

### Rename atomicity

- Tmp file placed in the same directory as target → same volume by
  construction.
- `os.Rename` on Windows → `MoveFileExW(MOVEFILE_REPLACE_EXISTING)`.
- Retry on `ERROR_SHARING_VIOLATION` (code 32) with exponential backoff:
  50 ms base, 10 attempts, ≤25 s total. Covers Windows Defender + indexer
  scan windows.

### Volume pre-flight

At ritual startup, assert user-data root resides on:
- Fixed drive (`GetDriveType == DRIVE_FIXED`).
- Not a UNC path (`\\server\share`).
- Not a known sync-folder root (OneDrive / Dropbox / iCloud Drive detected
  via known env vars or reparse points).

Any violation → fail-fast with clear error. Document supported environments
in README.

### Long paths

Go 1.25 (per `go.mod`) auto-prefixes `\\?\` for paths > 248 chars. No code
change needed.

### Read-only attribute

Before apply's rename-over:
```go
if info, _ := os.Stat(dst); info != nil && info.Mode()&0200 == 0 {
    _ = os.Chmod(dst, 0644)
}
```

Handles user-restored-backup edge case.

### Antivirus exclusion (operator guidance, not ritual-managed)

Document: adding `%APPDATA%/ritual/` to Windows Defender real-time-scan
exclusions eliminates sharing-violation retries and improves throughput.
Ritual does NOT manage AV settings.

## Compression

`zstd` level 3 (`SpeedDefault`) via `github.com/klauspost/compress/zstd`.
Locked per-spec — runtime-unconfigurable. Deterministic output at this
level means two clients producing identical raw bytes produce identical
compressed bytes, so content-addressed dedup works across clients.
Uniform path: every blob is compressed; no size threshold, no extension
skip list, no format-marker byte.

All measurement tables (level trade-offs, per-extension ratios,
dictionary experiments, tar vs per-file, streaming backpressure) live
in [Research Artifact § Claims ↔ Evidence](#claims--evidence). Pointing,
not restating, per `feedback_no_doc_duplication`.

## State Machine Integration

### Chain (nine stages, verb-aligned)

```
checking → pulling → acquiring → running → committing → pruning(local) → pushing → pruning(remote) → unlocking → ∎
```

Package layout under `internal/core/stages/`:

| Stage | Package | Body |
|---|---|---|
| `checking` | `stages/checking/` | run `[]ConditionService` |
| `pulling` | `stages/pulling/` | `Puller.Pull(headResolver())` then `Applier.Apply(id)` |
| `acquiring` | `stages/acquiring/` | `Locker.Acquire(ctx)` |
| `running` | `stages/running/` | subprocess + heartbeat goroutine (`Locker.Heartbeat`) |
| `committing` | `stages/committing/` | `Committer.Commit(targets)` writes `rs.RefID` |
| `pruning` (local) | `stages/pruning/` | local `Retainer` + `Collector` |
| `pushing` | `stages/pushing/` | `Pusher.Push(rs.RefID)` |
| `pruning` (remote) | `stages/pruning/` (second instance) | remote `Retainer` + `Collector` |
| `unlocking` | `stages/unlocking/` | `Locker.Release(ctx)` |
| `failed` | `stages/failed/` | parks `rs.Err`; retry routes back to origin stage |

`pruning.New([]Job, bus, onFail)` is wired twice at the composition root —
once with local jobs, once with remote jobs. Stage package is reused; two
runtime instances.

`RunState` gains one field: `RefID domain.RefID`. `committing` writes it,
`pushing` reads it. `pulling` uses a head-resolver closure injected at
the composition root (`List("refs/")` → max timestamp).

Verbs are dependencies injected into stages. Each stage invokes its
verb directly from `Run()` and chooses its successor from the result.
No separate coordinator; the chain IS the coordinator.

### Retention pairing (load-bearing)

Retention is NOT a terminal tail. It runs paired with the verb that
creates new refs, so a network flake during retention cannot hoard
objects that a later session never cleans:

- `committing` → `pruning(local)` → `pushing`
- `pushing` → `pruning(remote)` → `unlocking`

If `committing` fails, `pushing` never runs and remote state is
untouched. If `pushing` fails, remote retention never runs — the next
successful push's remote pruning sweeps whatever this session left
behind (content-addressed blobs; idempotent).

### Live-ticker (inside RunningState)

```
tick        → Commit(Amend=rs.RefID) → local Retain + Collect        (local only; no remote)
pushCadence → Push(rs.RefID)         → remote Retain + Collect
```

Amend never triggers remote retention. Only the `pushing` stage (or
live-ticker's push cadence) does. The chain's post-exit path uses the
same two pruning invocations so there is one code path, not two.

### Sequence

One picture of a normal session, top to bottom. Each row is time.

```
 Stage            │ Verbs / events
──────────────────┼────────────────────────────────────────────────────────
 checking         │  ConditionService checks (disk, RAM, Java, volume)
 pulling          │  Pull(headResolver())   ──► R2 GET refs/*, objects/{h}
                  │  Apply(id)              ──► materialise instance/ from blobs
 acquiring        │  Locker.Acquire         ──► R2 PUT lock (conditional)
                  │                          └─ lease clock starts; sessionId pinned
 running          │  ┌ Minecraft executes ──────────────────────────────────┐
                  │  │ ticker:                                              │
                  │  │   Flush (save-all flush); Commit(Amend=rs.RefID)     │
                  │  │   local Retain + Collect                             │
                  │  │   push cadence: Push + remote Retain + Collect       │
                  │  │ heartbeat goroutine: Locker.Heartbeat                │
                  │  └─ events: Commit/Push/Retention/GC Started/Finished  ─┘
 committing       │  Commit(CommitOpts{Targets}) → rs.RefID
 pruning(local)   │  local Retain (Last: 2) + Collect
 pushing          │  Push(rs.RefID)
 pruning(remote)  │  remote Retain (Last/Daily/Weekly/Monthly) + Collect
 unlocking        │  Locker.Release         ──► R2 DELETE lock
                  │                                                          ↓
 (failed)         │  per-origin retry via failed-stage; rs.Err parked
```

Cross-cutting: the throughput-tap decorator (see [Events](#events))
ticks every 1 s in every state that touches `StorageRepository`, emitting
`ThroughputInfo` regardless of which verb is active.

## Events

Per-stage lifecycle (started / finished / failed) via `ports.EventBus`.
Event types colocated with emitters. Progress events are aggregated from
decorator-layer events — **verbs do not emit progress**.

### Verb lifecycle events

- `PullStartedInfo{RunID, RawTotal, WireTotal, Blobs}`, `PullFinishedInfo{RunID, Err}`
- `ApplyStartedInfo{RunID, RawTotal, Files}`, `ApplyFinishedInfo{RunID, Err}`
- `CommitStartedInfo{RunID, RawTotal, Files}`, `CommitFinishedInfo{RunID, Err, ID RefID}`
- `PushStartedInfo{RunID, RawTotal, WireTotal, Blobs}`, `PushFinishedInfo{RunID, Err}`
- `RetentionStartedInfo`, `RetentionFinishedInfo`
- `GCStartedInfo`, `GCFinishedInfo`

Started events carry the plan totals (computed by the verb's plan step).
Finished events carry success/error. Nothing between — progress granularity
comes from decorator events, not verb emission.

### ACID-clean progress model

Progress consists of two orthogonal signals:

1. **Durable progress (bar)** — raw bytes confirmed at the verb's commit
   gate. Monotonic within a verb. Advances by whole-blob / whole-file
   chunks. Used for "X / Y MB done" bar.
2. **Wire throughput (speed)** — compressed bytes flowing through HTTP
   body streams, live. Used for "N Mb/s" label and ETA. Not a progress
   claim; a liveness signal.

The bar never credits in-flight bytes — ACID forbids claiming bytes durable
before the commit gate. Content-Length-based within-file smoothing is
rejected for the same reason.

**Commit gate per verb:**

| Verb | Durable when |
|---|---|
| Pull | streamed xxhash equals key AND fsync of `objects/{h}` succeeded |
| Apply | `rename(.ritualapply.tmp → instance/path)` returned success |
| Commit | local blob write stream hash-verified at `objects/{h}` |
| Push | remote `PutStream` returned 200 for `objects/{h}` |

Verbs run sequentially (pull → apply, or commit → push). Each verb owns
its own bar; no global combined bar. UI sequences phases.

### Decorator-emitted events

`ObservedStorage` emits per-port-method:

- `GetStreamStarted{ReqID, Key, Size}`, `GetStreamRead{ReqID, Delta}`, `GetStreamFinished{ReqID, Key, Total, Err}`
- `PutStreamStarted{ReqID, Key, Size}`, `PutStreamWrote{ReqID, Delta}`, `PutStreamFinished{ReqID, Key, Total, Err}`
- `RenameFinished{From, To, Err}`, `ExistsFinished{Key, Exists, Err}`, `ListFinished{Prefix, Count, Err}`, `DeleteFinished{Key, Err}`

`CompressingStorage` emits integrity events:

- `BlobReadVerified{Hash, RawSize}` — GET stream reached EOF AND streamed
  xxhash equals key.
- `BlobWritePersisted{Hash, RawSize}` — PUT/local write completed AND
  streamed xxhash equals target.
- `BlobIntegrityFailed{Hash, Got, Want}` — mismatch surfaced loudly.

Every event implements `ports.Event` with a single `EventKind() string`
method. Subscribers type-switch on the concrete types they care about;
unknown events are ignored.

### Progress aggregator

A single aggregator (`internal/core/progress`) subscribes to the bus,
reduces events into per-verb progress state, and republishes typed
progress events keyed by RunID + verb:

```go
type ProgressInfo struct {
    RunID        string
    Verb         string   // "pull", "apply", "commit", "push"
    RawDone      int64    // durable bytes, ACID-gated
    RawTotal     int64    // from {Verb}Started
    WireRead     int64    // in-flight — only for pull/push; zero for apply/commit
    WireTotal    int64    // from {Verb}Started; zero where inapplicable
    BlobsDone    int      // items past commit gate
    BlobsTotal   int
}
```

Transition rules (pull shown; push symmetric; apply/commit skip wire):

| Input event | State change |
|---|---|
| `PullStarted{R, W, N}` | `{RawTotal:R, WireTotal:W, BlobsTotal:N, rest:0}` |
| `GetStreamRead{Delta:d}` | `WireRead += d` |
| `BlobReadVerified{RawSize:s}` | `RawDone += s; BlobsDone += 1` |
| `PullFinished` | final emit; reset on next `PullStarted` |

Aggregator is a pure reducer over event streams. Tested without storage
via synthetic event sequences.

### Subscribers are unopinionated

Log subscribers type-assert `EventKind()` and format uniformly via `%+v`.
GUI subscribers filter for `ProgressInfo` + chosen lifecycle events. Zero
subscribers is valid — emitters do not care who listens.

Consequence: adding a new event type requires no change in existing
subscribers. Each subscriber owns its own filter.

### Throughput ticker (ETA + Mb/s)

Independent goroutine, 1 s cadence, snapshots `ObservedStorage`'s wire
counters, computes ETA, emits `ThroughputInfo`:

```go
type ThroughputInfo struct {
    RunID        string
    Verb         string         // "pull" | "push"; zero for non-wire verbs
    Elapsed      time.Duration
    ETA          time.Duration  // (WireTotal - WireRead) / InstWireBps
    WireRead     int64
    WireTotal    int64          // from {Verb}Started
    InstWireBps  float64        // (wire_now - wire_last) / dt
    AvgWireBps   float64        // wire_now / elapsed
    ActiveWorkers int
    QueueLen      int
    RetryCount    int64
}
```

ETA and Mb/s derive from **wire** (compressed) bytes, not raw. Wire bytes
answer "is the pipe alive" and "when will the network work finish"; raw
durable bytes answer "how much content is safe" (the bar). The two
signals never contaminate each other.

### Cadence

1 s tick, regardless of read rate. Per-`Read` emission and byte-milestone
emission were both tried in POC and rejected — UI wants predictable cadence
for smooth rendering.

### Decorator chain (composition-root order, outer → inner)

```
ObservedStorage         ← emits GetStream/PutStream lifecycle + Read/Wrote deltas
    └─ CompressingStorage   ← zstd encode/decode + BlobReadVerified / BlobWritePersisted
        └─ R2Repository      ← AWS SDK v2
```

Each layer is a `ports.StorageRepository` implementation. The aggregator
and ticker subscribe to `ports.EventBus`; they are not in the call path.

### Retry invariant

Inner-layer retries re-send compressed bytes but the caller's raw bytes
are fed only once. `ObservedStorage` counts wire `Read` / `Wrote` deltas
as they flow; retries produce extra wire bytes, but the raw-bar is still
gated on `BlobReadVerified` / `PutStreamFinished{Err:nil}` — one increment
per blob. Retries cannot advance the bar past 100%.

### Weak-snippet markers (from POC)

POC's `emitProgress` reads atomics from package-level vars. Production:

- Counters live on `ObservedStorage` struct (no globals).
- Ticker receives a `Snapshot()` handle via DI.
- Ticker publishes through `ports.EventBus`; no direct logger writes.
- Worker / queue counts come from injected `ThroughputSource` contributors,
  not from reading pool internals.

## User Stories

### US-1 — Normal session

> As an operator, I start ritual, play Minecraft, exit. I expect the world
> to be restored from the latest remote state on start, the server to run
> unmodified, and my changes pushed on exit.

Composition: `pull → apply → run → commit → push → retention → gc`.

### US-2 — Live-session safety (ticker)

> As an operator running a long session, I want periodic snapshots taken
> during gameplay without corrupting the world, so a crash doesn't lose
> hours of progress.

Composition: ticker fires `flusher.Flush` (`save-all flush`) then
`commit(...)` within `RunningState`. Amend between ticks; push on ticker
cadence or session-end. Autosave is already off from boot (running-stage
writes `save-off` once at readiness) and stays off for the session.

### US-3 — Amend collapse

> As a user playing repeatedly in the same region, I don't want ritual to
> upload intermediate tick snapshots of the same chunks — only the final
> state should cross the wire.

Composition: `commit(Amend=D_prev)` on each tick replaces the local draft.
Intermediate blobs orphan locally; reaped by localGC. Push uploads only the
final draft's new blobs.

### US-4 — Restore to past snapshot

> As an operator who notices corruption introduced during a session, I want
> to restore the world to a known-good manifest from the previous session.

Composition: `pull(T) → apply(T)` against arbitrary past timestamp. Server
must be stopped.

### US-5 — Target change (patch)

> As an operator installing a new mod pack, I want to add `forge/**` to the
> synced tree without waiting for a full world re-walk.

Composition: clone HEAD, edit targets, validate, write local manifest,
push. No commit (no new blobs). Retention + GC follow.

### US-6 — Crash recovery

> As an operator whose ritual was killed mid-push, I want the next session
> to resume cleanly without manual intervention and without corrupting
> remote state.

Composition: each verb idempotent. Next session re-attempts from whichever
verb's post-condition wasn't met. Lock lease auto-releases on writer
crash.

### US-7 — Cross-host resume

> As a team, when Alice's session crashes and Bob starts next, Bob should
> pick up from Alice's last successful push state, not earlier.

Composition: session lock on remote. Bob blocks until Alice's lease
expires (or explicit cleanup), then proceeds from the latest remote HEAD.

### US-8 — Self-service Explorer restore

> As a user uncomfortable with CLI tools, I want to copy files from a
> recent local backup directory into my worlds folder using Explorer.

The local `objects/` cache is content-addressed. Self-service restore from
local cache requires GUI tooling (CLI assisted) because blob names are
hashes, not paths. Non-goal for v2.1 launch; planned as GUI-assisted
"restore from local snapshot" panel.

## Flows to Check (end-to-end scenarios)

### F-1: Cold start, remote pre-populated

Pre: remote HEAD at T; local empty.

```
acquireLock()
pull(T)               → blobs fetched, manifest cached
apply(T)              → worlds/ + server/ materialised
runServer()
stopServer()
commit(CommitOpts{})  → D
push(D)               → remote [T, T2]
retention + gc
releaseLock()
```

Verify: worlds/ + server/ byte-equal to remote content. Second host's
`pull(T2)` reproduces same state.

### F-2: Live-ticker with amend

Pre: in RunningState.

```
boot: running-stage writes "save-off" once at readiness; autosave off for session.
tick 1: flush; commit()              → D1
        push(D1)                     → remote [T1]
        retention keeps [T1]; gc no-op (all blobs referenced)
tick 2: flush; commit(Amend=D1)      → D2
tick 3: flush; commit(Amend=D2)      → D3
        push(D3)                     → remote [T1, T3]
        retention(last1) drops T1
        gc sweeps T1's exclusive blobs remotely
session end: commit(Amend=D3) → D4; push(D4); retention; gc
```

Verify:
- `save-off` written exactly once per session (at readiness, never re-enabled).
- `save-all flush` issued once per tick, before the commit walk.
- Intermediate tick blobs (D2's unique hashes) never leave local disk.
- Remote object count strictly decreasing as retention prunes.

### F-3: Restore to past timestamp

Pre: remote has historical manifests; operator picks T_old.

```
stopServer()
acquireLock()
pull(T_old)
apply(T_old)          → instance/ rewritten to old state
runServer()           ← optional; may just restore without running
commit(Parent=T_old) → D (if played)
push(D)               → remote [..., T_old, ..., D]
```

Verify: worlds/ + server/ match T_old post-apply. New commit's parent =
T_old (branch by restore). Retention treats D as newest.

### F-4: Patch (target edit, no data change)

Pre: HEAD is T.

```
acquireLock()
m := cloneHEAD()
m.Targets = addTarget("server/forge/**")
validate(m)           ← superset of old targets, no orphan check needed
writeLocalManifest(m)
push(m.ID)            → remote [T, m.ID]
retention + gc
releaseLock()
```

Verify: no commit needed; push uploads only manifest. Subsequent session
sees expanded targets; walks include `server/forge/`.

### F-5: Crash mid-push recovery

Pre: push starts, process killed after some blob uploads, before manifest
PUT.

```
Session A: push(D) → blob set partially uploaded; manifest PUT — killed.
Remote: objects/{hash1..N} (some present); no new manifest.

Session B starts (Alice's lease expired):
  acquireLock()
  pull(HEAD)          → old HEAD (D never landed)
  apply
  run
  commit              → D' (possibly identical objects to D)
  push(D')            → blobs Exists-check skips already-uploaded; manifest
                        PUT succeeds.
  retention           → drops aged, if applicable.
  gc                  → sweeps any orphan blobs from Alice's partial attempt.
```

Verify: no data loss; Alice's local manifest (if any) untouched on her
machine; Bob's session advances state cleanly.

### F-6: Amend + failed push

Pre: D1 already pushed; amend in-flight.

```
tick 1: commit(nil)       → D1; push(D1) → remote [T1]
tick 2: commit(Amend=D1)  → D2 local
tick 3: push(D2)          → network failure mid-upload
Remote: [T1] + some blobs of D2 (orphan).

Session retry:
  push(D2)                → conditional-PUT skips uploaded blobs; manifest
                            PUT succeeds.
Remote: [T1, T2]; retention(last1) drops T1.
GC sweeps D2's orphan blobs from the failed attempt (now referenced by T2)
plus T1's exclusive blobs (now unreferenced).
```

Verify: no double-upload; retention collapses after success.

### F-7: Two-host race

Pre: Alice starts, crashes; Bob starts.

```
Alice: acquireLock → ✓. Some operations. Crash.
Remote lock payload persists with Alice's lockID; TTL not yet expired.

Bob:   acquireLock → 412.
Bob:   fetch lock payload. Now < expiry.
Bob:   abort "another session running, expires {expiry}".

Operator: ritual unlock --force  (OR waits for TTL).
Bob:   retries acquireLock → ✓.
```

Verify: Bob cannot proceed without lock; manual unlock is the escape hatch;
stale locks self-expire after TTL.

### F-8: Init on empty remote

Pre: remote `refs/` absent; local has populated `instance/` (from some
setup flow); no prior ritual state.

```
ritual init
acquireLock           (first-ever lock)
assert empty remote   (HeadObject refs/HEAD.json → 404 is fine; any
                       refs/* present → abort)
commit(Parent=nil, Targets=DefaultTargets)
push(draftID) with If-None-Match: * on manifest PUT
releaseLock
```

On failure: delete any uploaded blobs + release lock. Either full commit-
push or nothing.

Mock `StorageRepository`. One test function per scenario — no table-

**Pull**:
- Empty manifest → no ops.

- Integrity fail on decompression → blob treated as absent, refetched;
  persistent fail surfaces error.

- Empty instance/ + non-empty manifest → every path materialised.

- Post-stop path → walk + hash + store (no flush; server is dead).
- Live-ticker path → caller issues `save-all flush` before Commit runs.
- Target override → new targets validated against walked paths.
- Mtime-optimised walk: unchanged files carry hash forward (with
  size-equality guard).

**Commit (amend)**:
- Old draft replaced; parent inherited.
- Amend of pushed manifest → HEAD-check rejects with 412-equivalent.
- Orphan blobs flagged for localGC.
- Both manifests momentarily exist during crash between write-new and
  delete-old.

**Push**:
- All blobs already remote → only manifest PUT.
- Some blobs missing → uploaded, then manifest PUT.
- Blob upload failure → retry per blob.
- Manifest If-None-Match failure (init) → abort, no blob cleanup.
- Idempotent retry: same manifest, same blobs → no-op.

- Sparse history (fewer entries than budget) → everything kept.

- Drop list → each key Deleted.
- Delete failures → fail-continue; other drops proceed.

**GC**:
- All blobs referenced → zero deletes.
- Orphan blob → deleted.
- Multiple manifests → union live-set.

## Migration from v2

### Detection

First v2.1 session after binary upgrade lists remote: if `refs/*.json`
absent, treat as first run — full walk + full upload. Same trigger as v2's
`FullWorldScanner` on empty xxhash_map.

`ManifestVersion` field stays pinned at `"2.0.0"` (alpha; no version bumps).
Shape detection uses directory presence.

### v2 remote cleanup

After successful first v2.1 push + retention + gc:

- Delete `sync/*` prefix (v2 staging dirs — obsolete).
- Delete `worlds/*` prefix (replaced by `objects/` + manifest).
- Delete `backups/*` v2 format (replaced by `refs/*.json`).

One-shot step. If cleanup fails, next session retries — the v2.1 commit has
already succeeded, world state is safe.

### Mixed-version prevention

`RitualUpdater` already enforces minimum binary version via manifest. First
v2.1 release bumps minimum binary — all clients auto-update before touching
worlds. No mixed scenario possible.

### Backwards reading

v2.1 client reading v2 remote → detects absent `refs/` prefix → full
upload. v2 client reading v2.1 remote → never happens; auto-update
enforced.

## Implementation Phases

### Rollout strategy — strangler, parallel namespace

v2.1 code lives alongside v2 until the flip. **No edits to v2 files during
phases 1–5.** If a v2 bug forces a touch, fix and merge separately, then
rebase v2.1 work. This keeps every intermediate commit compiling and
tests green.

| Namespace | v2 (frozen during transition) | v2.1 (new) |
|---|---|---|
| Domain type | `domain.Manifest` | `domain.Ref` (new file `ref.go`) |
| Port | `ports.ManifestStore` | (dropped — `StorageRepository` V2 used directly; ref helpers live in `domain/ref.go`) |
| Remote prefix | `refs/` | `refs/` |
| Local dir | `refs/` | `refs/` |
| ID type | `string` (timestamp) | `domain.RefID` (string alias, `YYYY-MM-DDTHH-MM-SS.mmmZ`) |

## Storage V2 Migration — Epic

Phase A #1 (streaming `StorageRepository` rewrite) is decomposed into a set
of atomic stories. Each story is self-contained: an autonomous agent can
pick any `TODO` story whose `blocks_on` is satisfied, execute it, and mark
it `DONE` without asking for context. The spec is the single source of
truth for scope, acceptance, and progress.

### Global decisions (apply to every story)

| Decision | Choice |
|---|---|
| Migration shape | Strangler on existing interface |
| V2 method names | `GetStream`, `PutStream` |
| New method | `Exists` (no V1/V2 split) |
| `Rename` | Deprecated immediately, no V2 variant |
| Deprecation mechanism | `// Deprecated:` doc comment (SA1019) |
| V2 body type | `io.ReadSeeker` |
| Observed decorator | Implements V2 alongside V1 |
| `CompressingStorage` | V2-only new decorator for `objects/` |

### Story schema

Every story below uses this structure, machine-parseable:

```
### STORAGE-<n>: <title>
status:       TODO | IN_PROGRESS | DONE | BLOCKED | ABANDONED
owner:        <name or agent-id>
blocks_on:    [STORAGE-<m>, ...] | none
blocks:       [STORAGE-<m>, ...] | none
estimate:     <commits expected>
commits:      [<sha>, ...]    ← populated as work lands
files:
  new:        [path, ...]
  modified:   [path, ...]
  deleted:    [path, ...]
acceptance:
  - [ ] <checkbox>
verification: <command / assertion a downstream agent can run>
```

An agent may only pick a story when `status == TODO` AND every story in
`blocks_on` has `status == DONE`. On completion, agent sets `status =
DONE`, populates `commits`, and ticks every `[ ]` acceptance box.

## Superseded Concepts (explicitly dead)

| Concept | Why dead |
|---|---|
| `.ritual/` nested state dir | User-data root IS the tool-owned scope |
| `.blob.zst` blob key suffix | Bare hash is enough; suffix is ceremony |
| `refs/*.json.gz` compression | 20 KB plain JSON, not worth the gzip |
| `HEAD.json` pointer file | HEAD derived from max timestamp in list |
| Hardlink-based local backup + nlinks GC | Live-set mark-sweep is simpler, portable, correct |
| Per-subtree `.ritualsync` markers | Single manifest covers the whole tracked tree |
| On-disk `ritual.json` config | Targets live in the manifest |
| Binary defaults as runtime fallback | Init-only; runtime enforces invariant |
| Grace period in GC | Session lock + mark-sweep makes it unnecessary |
| Staging dirs on R2 | Content-addressed blobs are idempotent; no staging needed |
| `Rename = Copy + Delete` on R2 | Never rename; write new blob at new hash, GC the old |
| Path-addressed R2 keys | Keys are content hashes; paths live only in manifest JSON |
| Tar/streamer sync path | Per-file blobs; streamer package stays dead |
| Per-file `CopyObject` backup storm | Manifest IS the backup |
| Mixed backup-format retention parser | Only timestamped manifests exist |
| Single-manifest-per-side store | Multi-manifest store with list/get/put/delete |
| Schema version as evolution driver | Alpha — shape detection via prefix presence |
| v1→v2 tar migration code | Rolled out; residual dead code |
| `Ingest / Replicate / Commit` stage naming | Four verbs: pull / apply / commit / push |
| Three-stage push pipeline | Single `push` verb; retention + gc are peers |
| `If-Match` + HEAD-duplicate-filter retention patch | No HEAD pointer → no duplicate problem |
| Small-file (<128 B) raw-bytes compression skip | Uniform zstd on every object; ~6 B overhead on tiny blobs is trivial |
| Format-marker byte on stored objects | Only one format exists → nothing to discriminate |
| Extension-based incompressible skip (`.dat`, `.png`, `.zip`) | Uniform path; ratio ~100% on already-compressed types is acceptable |
| Manifest `.ritual.tmp`+rename ceremony (pull + commit) | Direct write; parse-fail on read = delete + refetch/re-commit is the integrity check |
| UUIDv4 nonce on apply tmp filenames | One worker per unique path in apply = no intra-session collision; `O_TRUNC` handles same-path retry |
| Generic `.ritual.tmp` suffix | Verb-scoped `{name}.ritual{scope}.tmp` convention — scope IS the ownership tag, sweep glob matches any scope |
